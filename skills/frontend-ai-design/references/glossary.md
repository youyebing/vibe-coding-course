## 第01 集｜Vibe Coding 术语课 01｜网页基础术语·七个高频词一次讲透，看完就能跟 AI 顺畅对线
> 主题：网页基础术语(共14词的第1期上·7词):从喊一声'帮我做个网页'到页面跑起来的整条链路上,AI回复里最常出现的 Frontend/DOM 等7个基础词,看懂就能跟 AI 顺畅对线

### Frontend｜前端
- **定义**：网页里你能看到、点到、输入的那一层都算前端;但账号到底建没建成,要等后端查完数据库才算数。
- **要点**：
  - 你能看到•点到•输入——都算前端;输入框、保存按钮、提示条都是前端的活
  - 口诀:前端管看得见,后端管办得成(请求发出后,后端查库/校验/写入,结果回来才知道'成功没')
- **给 AI 的句式**：向AI提需求时把'页面显示与交互'归为前端来描述;涉及查账号存不存在、校验、写入的活儿要意识到它在后端,别让浏览器端代码硬扛。
- **避坑**：保命提醒:密钥、价格、权限规则别写在前端——前端代码在浏览器里跑,谁都能打开看。

### Component｜组件
- **定义**：把会被反复使用的界面打包成一块'通用积木',哪里需要哪里插;改组件这一处,三个页面一起变。
- **要点**：
  - 例子:一张商品卡(图片/名称/价格/按钮)在首页、搜索结果、收藏页各用一次,别复制3份(以后要改3处)
  - 口诀:发现重复,抽成组件
  - 一次性的小图标,没必要硬拆
- **给 AI 的句式**：让AI把在多个页面重复出现的界面'抽成一个组件复用',之后统一改样式只需改组件这一处。
- **避坑**：别走极端:一个只用一次的小图标,没必要硬拆成组件。

### State｜状态
- **定义**：页面不是死的图片,它记得住'此刻'——悄悄记着的一张'小账',记录页面当下记住的事。
- **要点**：
  - 点保存→'正在提交…'(防止连点),请求结束再切到'保存成功'或'出错了'
  - 高亮的那一行 = 页面'此刻'的值;状态=页面当下记住的事
  - 状态只能来自真实操作、真实结果
- **给 AI 的句式**：描述交互需求时把状态流转说清楚,如'保存按钮经历待命→提交中→成功/出错,提交中要防止连点'。
- **代码**：`tip = '保存成功' // 提前写死`
- **避坑**：千万别在页面里提前写死一个'成功'——刷新一下就露馅了;状态只能来自真实操作、真实结果。

### Markdown｜轻量标记语言
- **定义**：一种轻量排版格式:写的时候是带着符号的纯文本(源码SOURCE),渲染出来就是干净排版(RENDERED);AI给的文档里全是#和**指的就是它。
- **要点**：
  - # 一级标题、**加粗**、- 列表项、三个反引号围起来是代码块
  - 特别适合写需求、文档和笔记:README.md、需求文档、笔记/知识库,纯文本文件放多少年都打得开
  - 它不是Word那种所见即所得
- **给 AI 的句式**：用Markdown写需求文档丢给AI,或要求AI以Markdown输出文档/笔记/代码块。
- **代码**：
```
# 周末计划
**周六爬山**
- 带水和零食
```
npm run dev
```
```
- **避坑**：注意它不是Word那种所见即所得——别往不支持Markdown的地方(如Word)直接粘。

### HTML｜网页结构语言
- **定义**：AI写出的'一堆尖括号+英文单词'就是它;用标签告诉浏览器'这是什么',负责搭网页骨架。
- **要点**：
  - 标签一般成对出现:开始标签 + 内容 + 结束标签(带/)
  - 常见标签:div通用容器、p段落、a链接、img图片、button按钮、input输入框
  - 分工:HTML定结构,CSS管外观,JS管交互——三个凑齐才是像样的网页
- **给 AI 的句式**：让AI'用HTML把页面骨架搭出来',说清页面有哪些标题、段落、链接、图片、按钮即可。
- **代码**：
```
<h1>小狸的主页</h1>
<p>我喜欢爬山和拍照。</p>
<a>看我的相册</a>
```

### CSS｜样式表
- **定义**：HTML是骨架,CSS是装修——颜色、字号、间距、圆角全归它管;基本单位是'规则'。
- **要点**：
  - 规则 = 选择器{声明}:选择器挑哪些元素,声明规定长什么样
  - 一个按钮可能同时命中好几条规则,浏览器按匹配范围/优先级/书写顺序算出最终胜出的样式
  - 想知道到底谁赢了:打开DevTools的Styles/Computed,一眼看出最终值
- **给 AI 的句式**：说外观需求时指明'用CSS实现'——颜色、字号、间距、圆角归CSS管;样式不如预期就提醒AI检查选择器命中范围与优先级。
- **代码**：
```
toolbar button { background: #767676; }  /*灰*/
.primary { background: #4338CA; }  /*蓝*/
/*两条都命中时按匹配范围/优先级/书写顺序,Computed 最终值=蓝*/
```

### DOM｜文档对象模型
- **定义**：把HTML文件交给浏览器,它不会照着打印,而是先把文档拆成一棵'活树',每个标签每段文字都是树上的一个节点,这棵树就叫DOM,页面照着它渲染。
- **要点**：
  - index.html源文件 → 浏览器内存视图(html文档根 > body主体 > ul列表 > li…)= DOM
  - 这棵树能被脚本修改(JS可改):点'新增',JS往树上插一个新节点,页面立刻多一条——哪怕原始文件里根本没有它
  - 口诀:源文件是图纸,DOM是浏览器搭出来、随时能改的'活树'
- **给 AI 的句式**：听到AI说'操作DOM'就是在说'用JS让页面内容增删改、立刻更新';想要不刷新就新增列表项,直接描述成'往列表插一项'即可。
- **代码**：
```
<ul>
  <li>写周报</li>
  <li>买牛奶</li>
</ul>
<!-- 浏览器渲染成 DOM 树:html > body > ul > li -->
```

> *收尾串联：七个词串成一条生产线:你喊一声'给我做个网页'——前端负责你看到的一切;重复出现的界面抽成组件;页面记住'当下'靠状态;跟AI写需求、做笔记用Markdown;骨架由HTML搭,好不好看交给CSS;浏览器再把它们变成一棵随时能改的活树DOM,页面就活了。网页基础术语一共14个,这期讲了前7个,还剩7个,下期见分晓。*

## 第02 集｜Vibe Coding 术语课：AI 写网页必懂的 7 个基础术语，一次讲透 | 网页基础术语 · 一期讲清验收标准
> 主题：AI交付网页的验收标准:同一个网页有4张脸(浏览器标签/搜索结果/分享卡片/桌面图标),再加2个'用起来'的兜底词,共7词;按'它最终显示在哪儿'去验收,别在代码里盯着

### Title Tag｜页面标题
- **定义**：写在<head>里的<title>,浏览器拿它当标签页的名字——你打开十个页面,靠它分得清哪个是哪个。
- **要点**：
  - 商品页例子:<title>降噪耳机•松果商店</title>,正文H1只写'降噪耳机'——两个字段各管各的
  - 搜索结果里那条蓝色标题可能参考你的title,也可能被重写,别承诺搜索结果一定长这样
  - 验收很简单:切两个商品页,看浏览器标签变不变,变了就对了
- **给 AI 的句式**：给AI需求时要求'每个页面写清<title>';验收时切换两个页面看浏览器标签有没有跟着变。
- **代码**：
```
<title>降噪耳机•松果商店</title>
<h1>降噪耳机</h1>
```
- **避坑**：title和H1是两个字段,改一个不会自动改另一个。

### Favicon｜网站图标
- **定义**：标签页上那个小方片图标,活儿很简单——帮人在一堆页面里认出你。
- **要点**：
  - 它出现在三个地方:标签页、书签栏、历史记录
  - 注意:它和页头Logo不是一回事,和搜索框里的功能图标也不是一回事;三个可以长得像,但换一个另外两个不会自己跟着变
  - 验收:别在页面里找,它压根不在页面里——去标签页、书签、历史记录里看,看不到就是没读到
- **给 AI 的句式**：给AI需求加一句'配favicon,用<link rel=icon>';验收时不看页面正文,去标签页/书签/历史记录看有没有图标。
- **代码**：`<link rel="icon" href="/favicon.svg">`
- **避坑**：Favicon ≠ 页头Logo ≠ 功能图标,三者不会自动同步,别在页面里找favicon。

### Page Metadata｜页面元数据
- **定义**：一个总称,不是单个开关——凡是放在<head>里描述这个网页、但不在正文里显示出来的信息都算元数据。
- **要点**：
  - title管浏览器标签,description可能变成搜索摘要,og:字段管链接分享,manifest管安装入口
  - 重点:它们的消费方不一样(浏览器/搜索/分享平台/安装系统),字段写对了只代表某一个消费方读到了
  - 验收句式:别问'元数据做完没有',要问'浏览器看到什么?搜索看到什么?分享出去是什么?装到桌面是什么?'
- **给 AI 的句式**：需求/验收时按消费方拆开问,而不是笼统说'把元数据写好';分享没图去查分享字段,装完启动路径错去查manifest,别一上来重写正文。
- **代码**：
```
<head>
  <title>Refund guide</title>
  <meta name="description" content="…">
  <meta property="og:image" content="…">
  <link rel="manifest" href="/manifest.json">
</head>
```
- **避坑**：别把元数据当成一个开关,做完就以为全好了——谁读它,就检查谁那一处。

### Open Graph｜分享预览
- **定义**：管链接'分享出去'这张脸:把链接甩到群里或社交平台时,别人看到的是有图有摘要的卡片还是一行光秃秃的网址,由og:*字段决定;很多人叫它OG。
- **要点**：
  - 用og:*描述分享预览,og四件套:og:title标题、og:description摘要、og:image配图、og:url地址
  - 只有普通title(no og:title/og:image/og:url)时:无预览图、分享出去是裸链接;补齐og四件套后卡片就有图有标题有摘要
  - 坑1:og:image这张图得是公网能直接打开的地址——只存在本机或要登录才能看的平台,抓不到
  - 坑2:平台会缓存——改完了要让它重新抓一次,再去看真实的卡片长什么样
- **给 AI 的句式**：需求写'转发到群/社交平台要有分享卡片',并配齐og:title/description/image/url四件套;验收要看真实分享卡片,源码对了不等于卡片更新了。
- **代码**：
```
<meta property="og:title" content="怎样做项目验收">
<meta property="og:description" content="…">
<meta property="og:image" content="https://…">
<meta property="og:url" content="https://vibehub.dev/verify">
```
- **避坑**：两个坑:og:image必须是公网可直接打开的地址;平台有缓存,改完要触发重新抓取后再看真实卡片。

### Web App Manifest｜Web 应用清单
- **定义**：描述网页被'安装到桌面'之后长什么样的配置文件(通常是个manifest.json):叫什么名字、用哪个图标、从哪个地址打开、像不像独立应用。
- **要点**：
  - 三步走:STEP1页面用<link rel=manifest>关联清单 → STEP2浏览器读取清单manifest.json → STEP3安装后启动
  - 四个字段:name名字、icons图标、start_url启动地址、display窗口形态(像独立应用还是像标签页)
  - 验收标准只有一个:装上之后看——桌面上的名字、图标、点开跳到哪儿;改完文件要删掉重装再看
  - 提醒:有manifest不等于能离线跑,离线是另一套东西
- **给 AI 的句式**：想让人把网页装到手机桌面,就让AI配manifest并写清name/icons/start_url/display;验收=真装上再看,别只盯文件。
- **代码**：
```
{
  "name": "VibeHub",
  "icons": [{ "src": "/icon-512.png" }],
  "start_url": "/?source=pwa",
  "display": "standalone"
}
```
- **避坑**：有Manifest能离线跑是误解——离线是另一套东西,别混为一谈;改完manifest要删掉重装再验收。

### Undo｜撤销
- **定义**：撤销上一步操作:在表格里删错一行,按一下它(Windows Ctrl+Z,Mac上是⌘+Z),那行内容原样回来。
- **要点**：
  - 它回来的不是重新生成的内容,是你动手之前那份快照,所以不会带进新错误
  - 和它配对的是重做Redo(Ctrl+Shift+Z,Mac ⌘+Shift+Z):把退掉的那步再做回来
  - 它有边界:通常只记得最近几步,页面一刷新/一关,历史就清了
- **给 AI 的句式**：给会误操作的地方(如表格删除行)安排撤销,或在需求里明确'要紧的删除要弹确认,别只靠撤销兜底'。
- **代码**：
```
撤销: Ctrl+Z  (Mac ⌘+Z)
重做: Ctrl+Shift+Z  (Mac ⌘+Shift+Z)
```
- **避坑**：撤销只退最近几步,刷新就没了——真正要紧的删除别指望撤销兜底,该谈确认就谈确认。

### Accessibility｜无障碍
- **定义**：AI回复里常见的缩写a11y(=a+11个字母+y):你测试页面用的是鼠标和好眼睛,但访客可能用键盘、读屏软件,或在太阳底下眯眼看手机;无障碍就是把这些场景都用起来。
- **要点**：
  - 检查点一:每张有信息的图片都配alt文字说明——图挂了或被读屏时,这段文字顶上
  - 检查点二:拔掉鼠标,只用Tab走一遍——每个按钮都能到达,焦点位置看得见,顺序不乱
  - 检查点三:正文和背景的对比度至少4.5:1,这条同时帮到所有在户外看手机的人
  - 无障碍不是做慈善,做好了普通用户也受益
- **给 AI 的句式**：验收前让AI过一遍无障碍三件套:信息图都有alt、纯键盘Tab能走通、正文/背景对比度≥4.5:1。
- **代码**：
```
alt="作品页示例：项目背景、过程和结果"
正文与背景对比度 ≥ 4.5:1
```
- **避坑**：别默认用户有鼠标和好眼睛——键盘可达、焦点可见、对比度够,是能直接检查的底线。

> *收尾串联：验收只看一处:它最终显示在哪儿——浏览器标签看页面标题(Title Tag)和网站图标(Favicon),搜索结果看页面元数据(Page Metadata),分享卡片看Open Graph,桌面图标看Web应用清单;每个词都对应一个你看得见的地方,去那儿验收,别在代码里盯着。剩下的撤销(Undo)和无障碍(Accessibility)是给用的人兜底的,不体现在某张脸上。下次AI交付页面,你就知道该打开哪扇门去看了——这七个词值得收藏起来对着验收。*

## 第03 集｜Vibe Coding 术语课：前端表单 7 个词，把报名页放心交代给 AI
> 主题：一张报名页上的七个表单控件(Button→Checkbox):点名的词说对,AI 交的货才不偏

### Button｜按钮
- **定义**：点一下就执行一个动作的控件,保存、提交、删除都算动作,动作有轻重之分。
- **要点**：
  - 按钮按轻重分级:最主要的动作用实心「主要」按钮,「次要」是取消/返回这类退一步的,「文字」最轻
  - 提交中状态要置灰、再点无效,防止手快连点重复提交
  - 删除、清空这类不可挽回的动作要用红色警示,点完先弹窗确认
- **给 AI 的句式**：「『提交』做成主要按钮;提交中置灰禁用,防止重复提交」
- **避坑**：反例:提交按钮被做成了跳转链接,点一下人就跑了(视频开头翻车案例)

### Link｜链接
- **定义**：住在文字里、点了能带你去别处(另一个页面/文档/下载地址)的元素。
- **要点**：
  - 嵌在正文里:报名须知、往期课程这类入口都做成链接,如「上课方式见报名须知」
  - 用颜色+下划线,让人一眼能看出可点
  - 报名须知页用新窗口打开,可返回报名页
- **给 AI 的句式**：「『报名须知』做成链接、新窗口打开;提交动作别用链接」
- **避坑**：提交、删除是按钮的活,链接负责带路;也别只写「点击这里」这种不说清去哪儿的文案

### Input｜输入框
- **定义**：收短文本的单行输入控件,一行就放得下,姓名、账号、邮箱、搜索词都用它。
- **要点**：
  - 标签要常驻看得见,别用灰字提示顶替
  - 格式错了要在框下方用红字说明原因(如「邮箱格式不对,请检查」),别只让框变色
  - 长内容别硬塞单行——想系统学 React 这类要换行的,该用多行文本框
- **给 AI 的句式**：「『邮箱』用单行输入框,标签常驻;出错时在框下方红字说明原因」
- **避坑**：反例:placeholder 当标签——打字后提示消失,用户不知道这格填啥

### Textarea｜多行文本框
- **定义**：跟输入框是一对的控件,不限行数、回车能换行,专门收一段话。
- **要点**：
  - 输入框一行、收一句话(如昵称);多行文本框收一段话
  - 评论、个人简介、给 AI 的提示词都归它管
  - 旁边常配实时字数统计,接近上限会变红提醒(示例 21/200)
- **给 AI 的句式**：「『想学什么』用多行文本框,限200字,实时显示剩余字数」
- **避坑**：一句话写得完的内容(如昵称)用回输入框即可,不必一律上多行文本框

### InputNumber｜数字输入框
- **定义**：只能填数字、还配了加减按钮的输入框,按一下数字就 +1/-1。
- **要点**：
  - 报名人数、买几件、库存、金额这类数量输入用它
  - 能设上下限:限1-10人,超出会被拦下,到顶后加号直接置灰
  - 演示:报名人数点加号数字往上跳,到10上限加号变灰
- **给 AI 的句式**：「『报名人数』用数字输入框,1-10 的整数,可点加减,超范围拦下」
- **避坑**：手机号、身份证看着像数字,其实是字符串、不能加减,别用步进器,用普通输入框

### Radio｜单选框
- **定义**：一组选项里只能挑一个的控件,选了新的会自动取消旧的。
- **要点**：
  - 适合选项不多、想让人一眼看全直接比较的场景(如场次:上午/下午/晚场)
  - 选项可以带说明:费用、时效写在旁边(免费约3天送达 / ¥8 明天18点前),一眼比明白
  - 点整行都能选中
- **给 AI 的句式**：「『场次』做成一组单选,只允许选一个;点整行都能选中」
- **避坑**：只剩一个需要确认的项(如同意条款)别用单选——那是复选框的活

### Checkbox｜复选框
- **定义**：每个选项独立、看上哪个勾哪个,能勾好几个也能一个不勾的控件。
- **要点**：
  - 多选都归它管:兴趣方向(前端/UI/AI/数据)全勾上,列表批量选人
  - 表头「全选」:勾了仨里俩,表头不亮全勾也不空着,而是出现一根「半选」横杠
  - 同意条款单独一个复选框:打勾=用户明确确认,勾选后才允许提交
- **给 AI 的句式**：「『兴趣方向』用复选框允许多选;『同意协议』单独一个复选框」
- **避坑**：一句话记住:单选=单选题;复选框=多选题,还能交白卷;同意类的勾选别跟普通多选混在一起

> *收尾串联：七个词一次到齐,每行都是给 AI 的一句指令:按钮做事、链接带路、输入框收一行、多行文本框收一段、数字输入框收数字、单选一组挑一个、复选框多选还能全不选——七个字段名说对,右边这张报名页一次成型。表单近亲 Switch 开关/Select 下拉/Slider 滑块留给后面的课。*

## 第04 集｜Vibe Coding 术语课｜前端控件 7 连：switch 到 tree-select，看 UI 不再懵
> 主题：七个前端控件都在替你做同一件事:让用户给程序「一个值」——值的形状越复杂,控件越高级

### Switch｜开关
- **定义**：拨一下就在开/关两种状态间翻转、程序里用一个布尔值就全装下的控件。
- **要点**：
  - 开和关就两个状态,程序里一个布尔值装下
  - 二选一的活都是它的:页面加个总开关,一键切深色模式
  - 演示:浅色 OFF → 拨一下变深色 ON,界面应声切换
- **给 AI 的句式**：「页面加个总开关,一键切深色模式」——说句加个开关,它端上来的就是 switch
- **避坑**：音量这种不能只有静音和最大的需求它不是(中间全是值)——那是 slider 的活

### slider｜滑块
- **定义**：一条轨道一个钮拖着走、在连续范围里取任意值(如音量停在 40%)的控件。
- **要点**：
  - 音量不能只有静音和最大,要能停在 40%——中间全是值
  - 拖到哪值就是哪儿,拖的时候常有气泡跟着报数(标配)
  - 给的是连续值
- **给 AI 的句式**：「音量做成 0~100 的滑杆」——AI 不会给你造输入框,直接上 slider
- **避坑**：别拿它当评分用:滑块给连续值,打分要离散档是 rate 的活

### rate｜评分
- **定义**：让用户点几下星就完成打分、不用写 200 字小作文的控件。
- **要点**：
  - 看完让用户点星打分,别让人写小作文
  - 星星给离散档:一颗星一个态度(演示 4 分)
  - 想要更细,加个半星开关
- **给 AI 的句式**：prompt 里说「这里来个五星评分」——AI 默认连悬停点亮都替你排好了
- **避坑**：注意 rate 跟 slider 不一样:滑块给连续值,星星给离散档

### select｜下拉选择
- **定义**：点开弹出列表、翻着挑一个的固定选项单选控件,不用敲键盘。
- **要点**：
  - 固定选项里单选,适合二三十个内:性别、套餐、城市
  - 选中的那行高亮,再点一下收起,框里回填干净(已选中:旗舰版)
  - 最大好处是用户不用打字,也就没有打错的可能
- **给 AI 的句式**：「套餐做下拉选择,固定选项二三十个内,别让用户打字」——别让 AI 图省事换成输入框
- **避坑**：选项一多 select 就顶不住(几百个城市下拉滚三屏)——那是 auto-complete 的活

### auto-complete｜自动补全
- **定义**：本质是输入框加联想,边打字边过滤候选(敲个「深」字,深圳自己浮上来)的控件。
- **要点**：
  - 选项多、用户心里大概知道叫什么:翻着选是 select,打着选是 auto-complete
  - 候选实时过滤:敲「深」字,杭州/深圳/西安/西宁只剩深圳,回车带走
  - 演示:回车选择深圳(一线城市)
- **给 AI 的句式**：「全国几百个城市,列表翻不动,边打边筛」——AI 就该上 auto-complete

### cascader｜级联选择
- **定义**：多级联动选择的控件,每级候选由上一级决定,省市区一次选完。
- **要点**：
  - 收货地址省市区三级,一次选完,别拆三个下拉
  - 点开第一列是省,选广东省,第二列自动刷出城市;选深圳市,第三列跟着出区
  - 每级候选由上一级决定,这个机制叫联动(广东省/深圳市/南山区)
- **给 AI 的句式**：prompt 里写「省市区三级地址」——AI 直接端 cascader,不会拆成三行下拉
- **避坑**：别把三级套娃拆成三个下拉让用户连选三遍,体验会崩

### tree-select｜树选择
- **定义**：在树形结构里勾多个节点、父子联动的选择控件,树形结构的多选只有它能干得干净。
- **要点**：
  - 适用:按组织架构选人,部门挂小组、小组挂成员,天生一棵树
  - 勾一个父节点,子节点全部自动带上(勾父带子)
  - 只勾了一部分子节点,父节点显示「半选」方块,提示没选全
- **给 AI 的句式**：「按组织架构选人:部门挂小组,组里还能多选」——树形结构的多选上 tree-select

> *收尾串联：七个词走一遍:开关存两态(布尔值)、滑块存连续值、评分存离散档、下拉翻着选一个、自动补全打着选、级联逐层下钻、树选择管父子多选——它们干的是同一件事:把用户给程序的一个值做得顺手、不出错。零件认全,AI 生成的界面你才真读得懂。*

## 第05 集｜Vibe Coding 术语课：AI 一说你就懵的 7 个前端 UI 词（form/label/date-picker 全真实演示）
> 主题：AI 反问「出生日期要不要用 date-picker」你就愣住的七个 UI 词,全住在一张网页表单里,逐个真实演示

### form｜表单
- **定义**：包住整张表单的外壳:把所有输入框打包成一张完整的表,提交时统一收集数据并做校验。
- **要点**：
  - form 不是某个输入框,而是包住所有输入框的那个外壳
  - 干三件事:打包字段成一张表、提交时统一收集数据、顺手做校验
  - 校验不过(密码太短、邮箱格式不对)在按钮下方标红提示(演示:密码至少8位)
- **给 AI 的句式**：「做一个报名表单:包一层 form,提交时校验」——AI 就知道这一页需要一组能提交、能校验的输入控件
- **代码**：`<form>`

### label｜标签
- **定义**：输入框旁边那行小字,告诉用户这一栏到底填什么(如「用户名」)。
- **要点**：
  - label=输入框旁边那行小字,这行字告诉你这一栏填什么
  - label 和输入框是绑定的:点一下这行小字,光标自动跳进输入框
  - 没有 label 的输入框,用户只能干瞪眼猜这栏填啥
- **给 AI 的句式**：「用户名输入框,label 写『用户名』」——别让它给你一排光秃秃的框
- **代码**：`<label htmlFor="uname">用户名</label>`
- **避坑**：没配 label,用户只能猜(演示:一个光秃秃的输入框,「这栏填啥??」)

### placeholder｜占位提示
- **定义**：输入框里面灰灰的提示字,告诉你这里该填什么格式,一动手输入就消失。
- **要点**：
  - label 在框外面、一直在、是字段名;placeholder 在框里面、一输入就消失、只是示例
  - 示例:邮箱框里灰字 name@example.com,提示邮箱格式长这样
  - 灰字消失 = 用户开始输入了
- **给 AI 的句式**：「邮箱框 placeholder 写『请输入邮箱』/『name@example.com』」
- **代码**：`placeholder="name@example.com"`
- **避坑**：记住:灰字是示例,不是填好的内容——别把 placeholder 当 label 用

### date-picker｜日期选择器
- **定义**：点开就是一张能翻月的小日历,点一下日期就按标准格式自动填好的选日期控件。
- **要点**：
  - 好处一:点开是小日历,能翻月(2026年9月)
  - 好处二:点一下,标准格式自动填好(2026-09-15)
  - 好处三:永远不会有 2月30号 这种不存在的日期
- **给 AI 的句式**：「出生日期用 date-picker」——AI 就知道要给你日历,而不是让你裸手打字
- **代码**：`value="2026-09-15"`
- **避坑**：让用户手打出厂日期,他可能给你敲个 2月30号出来

### time-picker｜时间选择器
- **定义**：跟 date-picker 是一对兄弟:date 管几月几号、time 管几点几分,点开是时间列表挑一个。
- **要点**：
  - 预约、排期、提醒这类界面都少不了它
  - 点开是一张时间列表(08:00~11:00 半小时一档),挑一个就行(已选 10:00)
  - 比手输靠谱,不会出现 25点 这种鬼时间
- **给 AI 的句式**：日期时间两个都要?直接说 date-time-picker,很多组件库都直接支持;「预约时间用 time-picker」
- **代码**：`value="10:00"`

### color-picker｜颜色选择器
- **定义**：把「选颜色」变成看得见的事的控件:面板上拖一拖、点一点,色块跟着变,同步给出 #FF6B81 这种色值。
- **要点**：
  - 做个人主页、后台设置,经常要让人挑个颜色当主题色
  - 拖一拖、点一点,左边色块跟着变
  - 所见即所得——面板挑完色值自动出来,不用懂色彩理论
- **给 AI 的句式**：「主题色加一个 color-picker」——AI 就会给你配好这个调色面板
- **代码**：`value="#FF6B81"`

### upload｜上传
- **定义**：收文件的入口,让用户交头像、附件、证件照的控件。
- **要点**：
  - 最常见的形态是虚线框:点它,或直接把文件拖进来
  - 放进来会出现小卡片:文件名/大小/进度(avatar.png 1.2MB 54%→100%)
  - 传完打个勾,显示「上传完成,可以提交了」
- **给 AI 的句式**：「头像加 upload,限 2MB」——AI 会连格式校验一起给你做掉
- **代码**：`<Upload maxCount={1} />`

> *收尾串联：学词不为了背,是为了跟 AI 下对单:把七个词串成一段话发给 AI——包一层 form 提交时校验;姓名输入框 label 写「姓名」;邮箱框 placeholder 写 name@example.com;出生日期用 date-picker;预约时间用 time-picker;主题色用 color-picker;证件上传用 upload 限 2MB——AI 基本一次把你想要的页面做出来,术语到位,改稿次数直接减半。*

## 第06 集｜前端UI·内容展示——八个组件，一次认全
> 主题：内容展示组件八件套：Table/List/Card/Tag/Badge/Avatar/Descriptions/Statistic，按“要对比/浏览/分组/标记/报数/认人/看详情/亮数据”选型

### Table｜表格
- **定义**：多列数据，横竖对齐成格子。
- **要点**：
  - 适合：多列对比
  - 一行行一列列，把数据码成格子
  - 典型如员工列表——姓名/部门/状态，一眼扫过去全清楚
- **给 AI 的句式**：要展示多列、需要逐行对比的数据时写：“这份员工列表用 Table 表格排成行列对齐的格子”。

### List｜列表
- **定义**：一条条竖着排，轻量内容流。
- **要点**：
  - 适合：消息流、文章列表
  - 比 Table 轻，每条带小图标和一段文字
  - 演示项：新消息提醒(3分钟前)、今日待办(2项进行中)、系统通知(刚刚)
- **给 AI 的句式**：消息流、文章列表这类一条条的轻量内容，告诉 AI“用 List 竖着一条条排”。

### Card｜卡片
- **定义**：把信息装进圆角盒子，图文可混排。
- **要点**：
  - 适合：独立小模块
  - 图文、按钮能放一起，整张还能点
  - 商品卡、教程卡都是这个套路，一排排好几个像货架
- **给 AI 的句式**：页面要放一批独立模块（教程卡/商品卡）时写：“每门课做成一张 Card 卡片，图文混排、整卡可点”。

### Tag｜标签
- **定义**：小色块，打分类标记。
- **要点**：
  - 适合：状态、分类筛选
  - 作用就一个：让人一秒看清这属于哪一类
  - 演示：进行中/已完成/高优/默认/停用，带 × 可删、可筛选
- **给 AI 的句式**：要给内容打分类/状态标记时说：“这些状态各加一个 Tag 小色块，进行中/已完成/高优”。
- **避坑**：别和 Badge 弄混：Tag 标文字、标分类；Badge 报数字、报状态（画面原文：Tag 标文字 Badge 报数字）。

### Badge｜徽标
- **定义**：图标角上的数字，报未读数量。
- **要点**：
  - 适合：消息提醒、计数
  - 挂在图标右上角的小数字，如 99+
  - 没读完的一眼就知道
- **给 AI 的句式**：消息图标要显示未读数时写：“右上角加 Badge 徽标，未读显示 99+”。
- **避坑**：别和 Tag 弄混：Badge 报数字/报状态，Tag 标文字/标分类。

### Avatar｜头像
- **定义**：用户的代表图形，圆形为主。
- **要点**：
  - 适合：评论、成员列表、聊天列表
  - 放首字母或一张脸，旁边还能挂在线小绿点
  - 评论区、聊天列表全靠它认人
- **给 AI 的句式**：用户列表/评论区要认人时说：“每个人配一个圆形 Avatar 头像，可显示首字母”。

### Descriptions｜描述列表
- **定义**：标签和值成对排开，只读详情。
- **要点**：
  - 适合：账号资料、详情页
  - 左一列标签右一列值，成对排开
  - 比 Table 更适合看单个对象的所有属性（用户名/邮箱/部门/入职时间）
- **给 AI 的句式**：展示单个对象的只读属性时说：“账号资料用 Descriptions 描述列表，字段名和值成对展示”。

### Statistic｜统计数值
- **定义**：大数字＋单位＋趋势。
- **要点**：
  - 适合：数据大屏、KPI 卡
  - 把最重要的数字放到最大，加单位和涨跌箭头
  - 演示：今日访问量 12,924（+12.5% 较昨日）、订单数、转化率
- **给 AI 的句式**：后台首页那一排 KPI 卡就是它：“顶部做一排 Statistic 统计数值，大数字＋涨跌趋势”。

> *收尾串联：八个组件一次记全：要对比用 Table、要浏览用 List、要分组用 Card、要标记用 Tag、要报数用 Badge、要认人用 Avatar、要看详情用 Descriptions、要亮数据用 Statistic。*

## 第07 集｜前端UI·内容展示——7 个组件，一次讲清（每个都配一个能动的真组件）
> 主题：内容展示组件第二版：Tabs/Segmented/Collapse/Timeline/Tree/Carousel/Empty，分别管分组、单选、收纳、顺序、层级、轮播、兜底

### Tabs｜标签页
- **定义**：页面上东西太多，就按概览、详情、评价分成几个标签，点哪个看哪个，一次只显示一块。
- **要点**：
  - 适合：内容能分组、页面不想拉太长
  - 类比：跟文件夹一排摆着，点哪个开哪个
  - 演示：智能手表 Pro 的 概览/详情/评价 三个标签
- **给 AI 的句式**：一个页面内容太多要分组时说：“把内容按 概览/详情/评价 做成 Tabs 标签页，一次只显示一块”。
- **代码**：`<Tabs />`
- **避坑**：标签别开太多，五六个以内；再多就该换别的结构了。

### Segmented｜分段控件
- **定义**：一排按钮，选中哪个，高亮块就滑到哪个，跟收音机选台一样，只能选一个。
- **要点**：
  - 适合：选项少、必须单选
  - 类比：跟 Tabs 长得像但更轻，只切换同一块区域的显示口径
  - 演示：周/月/切换“每日订单量”统计口径
- **给 AI 的句式**：同一区域要切换显示口径时说：“加 Segmented 分段控件，周/月两档单选切换”。
- **代码**：`<Segmented />`

### Collapse｜折叠面板
- **定义**：平时只露出标题，点一下才展开内容，再点一下收回去。
- **要点**：
  - 适合：FAQ 问答、设置分组、说明文档
  - 类比：像行李箱的夹层，合着省地方，用的时候拉开
  - 演示：如何开通会员？/支持退款吗？/发票怎么开？
- **给 AI 的句式**：问答/说明类内容不想占太多版面时说：“FAQ 用 Collapse 折叠面板，平时只露标题，点击展开”。
- **代码**：`<Collapse />`

### Timeline｜时间轴
- **定义**：一条线串起几个圆点，每个点是一件事，先后顺序一眼看清。
- **要点**：
  - 适合：物流轨迹、订单进度、项目里程碑
  - 演示：下单09:12→打包10:40→运输14:05→签收18:22
- **给 AI 的句式**：要表现事件先后顺序时说：“物流轨迹用 Timeline 时间轴，每个节点一件事”。
- **代码**：`<Timeline />`

### Tree｜树形控件
- **定义**：专管有层级的数据，父节点点开，冒出一排子节点，一层套一层。
- **要点**：
  - 适合：组织架构、文件目录、多级分类
  - 类比：跟电脑里的文件夹目录一模一样
  - 演示：项目文档→设计稿/代码/素材 逐层展开
- **给 AI 的句式**：要展示嵌套层级时说：“文件目录用 Tree 树形控件，父节点可展开子节点”。
- **代码**：`<Tree />`

### Carousel｜走马灯
- **定义**：多张图轮着放，自动翻页，也能手动划，一次看一张。
- **要点**：
  - 适合：首页 Banner、图片轮播、广告位
  - 类比：像商场橱窗的滚动屏，翻来翻去不重样
  - 演示：新品上市/限时特惠/会员专享多张轮播
- **给 AI 的句式**：首页要放轮播图时说：“顶部 Banner 做成 Carousel 走马灯，自动轮播可手动划”。
- **代码**：`<Carousel />`
- **避坑**：图片别放太多，超过五张，用户基本等不到看完。

### Empty｜空状态
- **定义**：数据还没来的时候，别让页面干巴巴空着，放个小插画，配一句“暂无数据”。
- **要点**：
  - 适合：购物车为空、搜索无结果、列表为空
  - 再给个“去添加”按钮，引导用户去操作
  - 演示：暂无数据＋小插画＋去添加按钮
- **给 AI 的句式**：列表没数据时写：“空状态用 Empty 组件，放插画和‘暂无数据’，加一个去添加按钮”。
- **代码**：`<Empty />`

> *收尾串联：七个组件一次记住：Tabs 管分组、Segmented 管单选、Collapse 管收纳、Timeline 管顺序、Tree 管层级、Carousel 管轮播、Empty 管兜底。*

## 第08 集｜Web 前端篇——10 个高频术语
> 主题：天天见却不一定叫得上名字的 10 个前端界面词：image/file/video/icon/App Icon/quote/Chat UI/Filter/chart/sort

### image｜图片
- **定义**：网页上的照片、插画、表情包，都是它。
- **要点**：
  - 想让 AI 加张图，说的就是它
  - 前端就一行 <img> 标签，加个 src 指路图片就出来了
- **给 AI 的句式**：“这里加一张商品图 image，用 <img> 引入”。
- **代码**：`<img src="photo.jpg">`

### file｜文件
- **定义**：就是那个上传文件的按钮/区域，点一下弹出你电脑里的文件管理器，选好文件就传上去了。
- **要点**：
  - 演示：把文件拖到这里，或从电脑中选择文件
  - 报告.docx、视频.mp4、照片.jpg 都能传
  - 前端一行 input 标签、type 设成 file 搞定
- **给 AI 的句式**：要上传功能时说：“加一个 file 上传控件，支持拖拽和选择文件”。
- **代码**：`<input type="file">`

### video｜视频
- **定义**：网页里内嵌的播放器：播放、暂停、进度条，控件全自带。
- **要点**：
  - 一个 video 标签加个 src 就能放，不用自己造轮子
  - 演示：播放条 00:17 / 04:56
- **给 AI 的句式**：“页面上内嵌播放这个视频，用 video 标签”。
- **代码**：`<video src="film.mp4">`

### icon｜图标
- **定义**：搜索框的放大镜、设置里的齿轮都是它；矢量图，放大缩小都不糊。
- **要点**：
  - 前端一般直接引现成的图标库，不用自己画
  - 画面提到图标库：lucide、iconify
- **给 AI 的句式**：“按钮上加一个搜索 icon，从图标库引入”。

### App Icon｜应用图标
- **定义**：手机桌面上那个方形 logo，代表一个应用。
- **要点**：
  - 开发时一个图标往往要做成好多尺寸，适配不同设备
  - 画面里的资源：asset/icon-512.png
- **给 AI 的句式**：要 PWA/桌面端 logo 时说：“准备一套 App Icon，含 512px 等多尺寸”。

### quote｜引用
- **定义**：别人的一段话，突出显示，左边一条竖线，一看就知道是引用。
- **要点**：
  - 对应标签叫 blockquote，样式现成
  - 演示：博客里引用名言 “Talk is cheap. Show me the code.”
- **给 AI 的句式**：“这段话做成 quote 引用块，左边一条竖线突出显示”。
- **代码**：`<blockquote>`

### Chat UI｜聊天界面
- **定义**：现在最常见的界面，AI 助手、客服都是它：左边你右边机器人，气泡一来一回，底下是输入框。
- **要点**：
  - 想做个聊天应用，跟 AI 说一声界面直接给你搭好
  - 演示：AI 助手问答，输入框“输入你的问题…”
- **给 AI 的句式**：“做一个 Chat UI 聊天界面，消息气泡左右分列，底部输入框”。

### Filter｜筛选/滤镜
- **定义**：筛东西是它，加滤镜也是它——同一个词两种用法。
- **要点**：
  - 电商页面按价格、销量、评分筛东西
  - CSS 里给图片加模糊、变黑白也是它
  - 常和排序搭在一起
- **给 AI 的句式**：“列表加一组 Filter 筛选条件：价格/销量/评分”。
- **代码**：`CSS filter`

### chart｜图表
- **定义**：把数字画成图形，一眼看懂。
- **要点**：
  - 柱状图、折线图、饼图都算 chart
  - 前端一般用现成的图表库，把数据丢进去它帮你画
  - 演示：本周数据 1-5 月
- **给 AI 的句式**：“这组统计数据画成 chart 柱状图”。
- **代码**：`<Chart data={...}/>`

### sort｜排序
- **定义**：让列表按价格从低到高、按时间从新到旧排。
- **要点**：
  - 界面上通常是个下拉框，或者两个小箭头
  - 演示：排序“价格从低到高”，帆布包 ¥29…蓝牙音箱 ¥359
  - 常和筛选搭在一起
- **给 AI 的句式**：“商品列表支持按价格 sort 排序”。
- **代码**：`sort by price`

> *收尾串联：结尾把十个术语整体列一遍：写代码的时候翻出来对照着看——image/file/video 是媒体三件套，icon/App Icon 管图标，quote/Chat UI 是内容块，Filter/chart/sort 管数据操作。*

## 第09 集｜前端：弹窗与提示——12 个组件
> 主题：网页里“点一下啪地冒出来、过两秒又自己消失”的那一类组件，细数能凑出 12 个，别再管所有弹窗都叫弹窗

### Alert｜警告提示
- **定义**：常驻在页面顶部、不会自己消失的提醒条，专门喊重要的事。
- **要点**：
  - 常驻不消失，是页面上的“常驻喇叭”
  - 黄条=提示：体验环境·数据每日 0 点重置
  - 红条=报错：提交失败·2 处填写有误，请检查后重试
- **给 AI 的句式**：页面上要有常驻提醒时说：“顶部放一个 Alert，提示体验环境数据每日 0 点重置”。
- **避坑**：与 Toast 相反：Alert 常驻不消失，适合重要提醒；轻量提醒别用它。

### Toast｜轻提示
- **定义**：右下角冒出一句“保存成功”，过两秒自己消失的小纸条，什么都不用你管。
- **要点**：
  - 特点是轻、不打断你正在做的事，瞄一眼就行
  - 演示：点“保存”后右下角浮出“保存成功”自动消失
- **给 AI 的句式**：操作成功的瞬时反馈说：“点保存后弹一个 Toast‘保存成功’，两秒自动消失”。

### Notification｜通知
- **定义**：右上角铃铛点开的一堆系统消息——消息会攒着，等你点开，像收件箱。
- **要点**：
  - 跟 Toast 的区别：通知攒着等你看，Toast 一闪而过
  - 演示：审核未通过（封面临摹比例过高）/系统维护通知/视频已发布
  - 可点“查看原因”直接跳过去处理
- **给 AI 的句式**：系统消息要留存可回看时说：“右上角铃铛做 Notification 通知中心，消息攒着等用户点开”。

### Modal｜弹窗
- **定义**：屏幕中间跳出个框，背后整个页面变灰点不了——模态弹窗，逼你先把手头这件事确认完。
- **要点**：
  - 演示：确认删除这个项目？删除后不可恢复（取消/确认删除二选一）
  - 重要、危险操作就得用弹窗拦一下
- **给 AI 的句式**：删除等危险操作说：“点删除后弹 Modal，确认删除这个项目？背后页面置灰不可点”。
- **避坑**：小确认别动不动就开大窗——轻量确认用 Popconfirm 气泡。

### Drawer｜抽屉
- **定义**：从屏幕边缘（右侧）滑出来的一块面板，背后的列表还看得见，不遮住全部。
- **要点**：
  - 演示：点任务行，右侧滑出任务详情（任务名称/截止日期/备注，关闭/保存）
  - 关键：它只是从边上抽出一层，不遮住全部内容
- **给 AI 的句式**：要看详情同时保留上下文时说：“点任务行从右侧滑出 Drawer 抽屉显示详情，背后列表保持可见”。

### Popconfirm｜气泡确认框
- **定义**：不弹大窗，就在按钮旁边冒出一句“确认删除这条记录？”的小气泡，取消/确定点完就完事儿。
- **要点**：
  - 适合轻量二次确认
  - 演示：删除按钮旁弹出 取消/确定
- **给 AI 的句式**：删除某一行时写：“行内删除加 Popconfirm 气泡确认框，就在按钮旁边确认”。
- **避坑**：小确认用气泡，别动不动就开大窗（Modal）。

### Popover｜气泡卡片
- **定义**：主动点开后浮出的一张详情小卡片，比如点一下头像，旁边浮出名字、职位、城市、查看主页。
- **要点**：
  - 演示：头像旁浮卡显示“产品经理·深圳·查看主页”
  - 区别：Tooltip 是悬停看一行字，Popover 是你主动点开的一张详情卡
- **给 AI 的句式**：点头像看资料时说：“点头像弹出 Popover 卡片，显示职位/城市/查看主页”。

### Tooltip｜文字提示
- **定义**：鼠标放上去，图标旁边飘出一行小字，解释这个按钮是干嘛的；鼠标一离开马上消失。
- **要点**：
  - UI 里最安静的存在：不点不弹不打扰
  - 演示：刷新/导出按钮旁悬停显示“查看操作帮助”
- **给 AI 的句式**：给图标按钮加解释时说：“悬停显示 Tooltip 文字提示，说明按钮作用”。

### Progress｜进度条
- **定义**：一条从 0 爬到 66% 的进度条，给等待中的用户一个反馈。
- **要点**：
  - 上传文件最怕没反馈：传没传完、卡没卡死，用户心里要有底
  - 演示：上传中心“设计终稿_v8.zip 上传中 66%”
  - 凡是需要等待的，都值得配一条进度条
- **给 AI 的句式**：上传/下载时说：“上传时显示 Progress 进度条，百分比实时更新”。

### Skeleton｜骨架屏
- **定义**：内容还在加载，先摆出一排灰色占位框，等数据真到了，内容“啪”地填进去。
- **要点**：
  - 别让用户盯着空白干等，先占好座
  - 演示：文章列表加载时显示灰色占位块
- **给 AI 的句式**：页面数据加载慢时说：“加载完成前先显示 Skeleton 骨架屏占位，数据到了再替换”。

### Result｜结果页
- **定义**：提交、付款这种大事做完后，先给一个明确的结果页，做完事有交代用户才安心。
- **要点**：
  - 演示：提交成功——审核结果将在 1-3 个工作日内通知你
  - 再给个下一步按钮：返回首页
- **给 AI 的句式**：表单提交成功后说：“跳转 Result 结果页，显示提交成功，再给一个返回首页按钮”。

### Spinner｜旋转加载指示器
- **定义**：加载慢的时候给个转圈，旁边写“正在保存…”，是所有反馈里最朴素的一个。
- **要点**：
  - 可要是没了它，用户真会以为程序卡死了
  - 演示：文档中心“正在保存…”转圈
  - 转圈虽小，必不可少
- **给 AI 的句式**：异步等待中说：“保存期间显示 Spinner 转圈＋‘正在保存…’”。

> *收尾串联：12 个到齐了：常驻喊话的是 Alert、一闪而过的是 Toast、攒着看的是 Notification、拦你一下的是 Modal、边上抽出来的是 Drawer、按钮旁小气泡是 Popconfirm、详情卡是 Popover、悬停科普的是 Tooltip、爬进度的是 Progress、站位的是 Skeleton、给交代的是 Result、一直转圈的是 Spinner。*

## 第10 集｜前端导航组件——九个术语一次讲清
> 主题：前端导航类组件九件：用户怎么找到内容的 Search/Breadcrumb/Pagination/BackTop/Steps/Anchor/Dropdown/Skiplink/Menu

### SEARCH｜搜索
- **定义**：内容一多，用户懒得一层层翻，直奔搜索框输关键词，它马上把沾边的都捞出来。
- **要点**：
  - 像问询台：输几个关键词，从一大堆内容里捞结果
  - 内容攒到靠人工翻都找不到的时候，就该装它
  - 演示：输入“退款”出现退款政策、订单退款进度
- **给 AI 的句式**：“内容多了，顶部加 SEARCH 搜索框，支持按名称/关键词检索”。

### BREADCRUMB｜面包屑
- **定义**：网页顶部那排“首页>分类>当前页”，标出你现在在哪个位置，还能一层层点回去。
- **要点**：
  - 名字来自童话：小孩沿路撒面包屑好认路回家
  - 页面层级深的网站离不开它
  - 不然用户逛着逛着就不知道自己在哪儿了
- **给 AI 的句式**：“详情页顶部加 BREADCRUMB 面包屑：首页>分类>当前页，可逐级点回”。

### PAGINATION｜分页
- **定义**：一个页面塞不下几千条数据，就切成很多页，底部给你一排 123 这样的翻页按钮。
- **要点**：
  - 用它的关键是别让用户迷路：现在在第几页、下一页是什么要一眼能看见
  - 最怕翻完一页内容整个变样
- **给 AI 的句式**：“列表数据量大，底部加 PAGINATION 分页，显示当前页和总页数”。

### BACKTOP｜回到顶部
- **定义**：页面特别长、一路滚到底后，右下角冒出来的向上小按钮，点一下“蹭”地回到顶部。
- **要点**：
  - 是导航里最省心的一个
  - 页面够长，就值得放一个
  - 省得手动再滚 10 分钟
- **给 AI 的句式**：“长页面右下角加 BACKTOP 回到顶部按钮，滚动出现”。

### STEPS｜步骤条
- **定义**：把第一步、第二步、第三步排成一条线摆在那，告诉你现在走到哪一步、后面还剩几步。
- **要点**：
  - 适合下单、注册、填资料这类多步流程
  - 用户心里有数，才愿意把整个流程走完
  - 演示：填写信息→确认订单→完成支付
- **给 AI 的句式**：“下单流程用 STEPS 步骤条：填写信息→确认订单→完成支付，高亮当前步”。

### ANCHOR｜锚点
- **定义**：一个页面特别长、讲了好几个话题时，在页面右边竖一个小目录，点一下直接跳到那一节。
- **要点**：
  - 像电梯里的楼层按钮，不用一层层爬
  - 演示：一、背景 / 二、方案设计 / 三、结论 电梯直达
- **给 AI 的句式**：“长文页面右侧加 ANCHOR 锚点目录，点击跳到对应章节”。

### DROPDOWN｜下拉菜单
- **定义**：选项一多全摊开太占地方，就把它们收进一个小抽屉：鼠标移上去或点一下，选项才展开。
- **要点**：
  - 最常见的是头像旁边那个“更多操作”：设置、退出
  - 它的本事是收纳
- **给 AI 的句式**：“把 设置/退出 收进头像旁的 DROPDOWN 下拉菜单，悬停或点击展开”。
- **避坑**：重要的操作也别藏太深，得让用户找得到。

### SKIPLINK｜跳过导航链接
- **定义**：放在页面最前面的一小段隐藏入口，按一下就直接跳到正文。
- **要点**：
  - 比较冷门但特别重要
  - 用键盘（Tab）操作网页的人，进页面不用一次次摸过导航
  - 这是做无障碍必备的细节
- **给 AI 的句式**：“页面最前面放一个 SKIPLINK 跳过导航链接，直达正文内容（无障碍）”。

### MENU｜导航菜单
- **定义**：顶部或侧边那一排入口：首页、产品、关于我们、联系——整个网站的骨架，靠它把页面串起来。
- **要点**：
  - 功能少的时候一行摆得下
  - 功能一多就得琢磨怎么分组、怎么收纳
  - 其他导航组件都长在这条栏上（画面原文）
- **给 AI 的句式**：“站点顶部做一排 MENU 导航菜单：首页/产品/关于我们/联系，产品下挂子项”。

> *收尾串联：九个导航组件齐了：搜索、面包屑、分页、回到顶部、步骤条、锚点、下拉菜单、跳过导航链接，还有压轴的导航菜单——以后 AI 写代码再碰上这些名字，就知道它们是干嘛的了。*

## 第11 集｜Vibe Coding 术语课：Hero？CTA？Navbar？一次讲透网页 10 大件
> 主题：网页 10 大件（页面级大区块）：Logo→Header→Navbar→Hero→CTA→SocialProof→UserVoice→Pricing→FAQ→Footer，从招牌、门头、导航、首屏、催单按钮到口碑、价格、答疑、页脚，讲透一张页面从上到下的大骨架，好按顺序给 AI 提需求

### Logo｜标志
- **定义**：你这家店的招牌：一个图形或名字的特殊写法，让人隔老远就能认出你是谁。
- **要点**：
  - 画面注释：图形 / 文字 / 组合
  - 演示店名「夜灯铺」，给几版图形加文字的组合
  - 跟 AI 说“给我设计个 logo”，挑一个顺眼的用就行
- **给 AI 的句式**：给 AI 说“给我设计个 Logo（图形+文字组合，多出几版）”，挑顺眼的用。

### Header｜页头
- **定义**：页面最顶上那一横条，店名、导航按钮都钉在这一条里，相当于店门口的门头。
- **要点**：
  - 顾客一抬头就知道这是谁家、卖什么的
  - 演示：夜灯铺——店名、菜单都收在条里
- **给 AI 的句式**：需求里写“顶部做 Header 页头”，店名和导航按钮就都会钉在最上面那条里。

### Navbar｜导航栏
- **定义**：一般嵌在页头里的一排小按钮（首页/产品/价格/联系），就是店里的指示牌，想去哪个区点一下就带过去。
- **要点**：
  - 演示：首页 / 产品 / 价格 / 联系 + 内容区
  - 做的时候把要哪几项列成清单发给 AI 就行
- **给 AI 的句式**：给 AI 需求时把栏目列成清单：“Navbar 导航栏放 首页/产品/价格/联系 这几项”。

### Hero｜首屏
- **定义**：网页打开后不用滚动就能看到的第一屏，整页最金贵的地方，因为顾客第一眼就看它。
- **要点**：
  - 把最大的字、最想说的一句话放这，再配一张大气点的图
  - 画面注释：一眼就知道你是谁 / 用一句话说清你卖什么
  - 往下滚才看得到的部分叫内容区
- **给 AI 的句式**：跟 AI 说“首屏（Hero）要够震撼、一句话说清卖什么、配大图”，它就明白。

### CTA｜行动召唤
- **定义**：全页最显眼的一颗扣子（免费试用/立即购买），放在最顺手的位置，就为了让你别犹豫、一点就下单。
- **要点**：
  - 直译“行动召唤”，其实就是那种特别显眼的按钮
  - 演示：免费试用
  - 画面注释：全页最显眼的一颗扣子
- **给 AI 的句式**：需求里写“页面放一个显眼 CTA 按钮：免费试用”，AI 会把它做得最突出。
- **避坑**：这种按钮别贪多：一页里一两个最显眼的就够了，多了反而没人点。

### SocialProof｜社会证明
- **定义**：晒合作过哪些大牌、多少人在用（如“100,000+ 团队正在用”），人是会随大流的，看到这么多人选心里就踏实。
- **要点**：
  - 典型做法：一行合作品牌的标志 + 一句“10万团队都在用”
  - 演示数字：35,714+ / 100,000+ 团队正在用
  - 帮新顾客建立信任
- **给 AI 的句式**：给 AI 说“加 SocialProof 社会证明：一排合作品牌 Logo + 10万团队正在用”。

### UserVoice｜用户心声
- **定义**：也叫用户评价：挑几条真实用户的夸奖贴出来，配上名字和头像——自己夸自己 100 句顶不过老顾客说一句。
- **要点**：
  - 演示：咖啡店主“排版省了大半天”、工作室主理人“风格统一看着舒服”、独立开发者“上线当天就来询价”
  - 位置好、不用大，两三条就够
- **给 AI 的句式**：需求里写“放几条 UserVoice 用户评价（用户心声），配名字和头像”。

### Pricing｜定价区
- **定义**：把收费方案摆成一排对比（免费版/进阶版/专业版），一栏一栏对着看，中间档常标着“最受欢迎”。
- **要点**：
  - 演示：免费版 ¥0 / 进阶版 ¥49 / 专业版 ¥199
  - 中间档标“最受欢迎”是小套路
  - 最想卖的那档放中间，两边价格一衬它就显得不贵了
- **给 AI 的句式**：说“Pricing 定价区：免费版¥0、进阶版¥49、专业版¥199 三档并排对比，中间档标最受欢迎”。

### FAQ｜常见问题
- **定义**：把顾客最爱问的几个问题提前写好、一问一答折起来放在页面靠后位置，顾客自己点开就能看，省客服口水。
- **要点**：
  - 演示问题：多少钱 / 能不能退款 / 数据放哪
  - 示例答案：有免费版，付费版按年付更划算
- **给 AI 的句式**：需求里写“页面靠后加 FAQ 常见问题：多少钱、能不能退款、数据放哪，一问一答可展开”。

### Footer｜页脚
- **定义**：页面最底下那一块，位置不起眼但该有的都有：联系方式、友情链接、备案号、版权声明，相当于店门口贴的那张纸。
- **要点**：
  - 平时没人细看，真要找信息的人一定会翻到这儿
  - 演示：© 2026 保留所有权利
- **给 AI 的句式**：需求里写“Footer 页脚：联系方式、友情链接、备案号、版权声明”。

> *收尾串联：回头看一个网页：招牌和门头（Logo、Header）在最上面，Navbar 导航带你走，Hero 首屏负责留人，CTA 按钮负责催单，SocialProof 口碑和 Pricing 价格负责说服，FAQ 提前答疑，最后 Footer 页脚收尾——下次让 AI 做页面，按这个从上到下的顺序提要求，它做出来的就是你想要的。*

## 第12 集｜Vibe Coding 术语课：跟 AI 要页面，先学会这 9 个网页布局词
> 主题：9 个网页布局骨架词：Card Grid/瀑布流/分屏/顶部导航/文档三栏/响应式/单页滚动/左侧栏/居中窄栏——补一个布局词，页面立刻照你的意思长（像点菜一样指挥 AI）

### Card Grid｜卡片网格
- **定义**：把内容切成一排排大小差不多的卡片，像超市货架：屏幕宽就多摆几列，变窄自动换行。
- **要点**：
  - 适合图片、商品、视频这类内容，立刻整整齐齐摆好
  - 画面提示词：说“用卡片网格排版”
  - 开场示例：“帮我做个卡片网格的图库页”
- **给 AI 的句式**：“用卡片网格排版图片/商品/视频”，或“帮我做个卡片网格的图库页”。

### Masonry｜瀑布流
- **定义**：图片站最爱的排法：卡片高矮不一样但不硬裁齐，下面自动续新卡，像水一样往下淌。
- **要点**：
  - 说“瀑布流”，AI 就知道图片保持原样、绝不强行剪裁
  - 演示站 vibecode.local/pins，新卡片从下面补进来
- **给 AI 的句式**：“瀑布流排版：图片保持原样、高矮不一地往下淌”。

### Split-screen｜分屏布局
- **定义**：首页左右各一半：左边放品牌介绍、右边直接给登录入口，对比感拉满；手机上放不下就自动改成上下叠。
- **要点**：
  - 说“分屏布局”，AI 会把两块内容对称安排得明明白白
  - 演示：ATELIER OS 登录页——左品牌介绍、右登录/工作台入口
- **给 AI 的句式**：“分屏布局：左边品牌介绍，右边登录入口”。

### Top Nav｜顶部导航
- **定义**：最经典的布局架子：上面横一条导航栏，下面全是内容区，用户一进来就知道往哪走。
- **要点**：
  - 官网、后台、工具站十有八九长这样
  - 演示：ViteHub——首页 / 关于 / 功能 / 联系 + 下方内容区
  - 画面提示词：说“顶部导航布局”
- **给 AI 的句式**：“顶部导航布局：导航栏在顶、下面是内容区”。

### Doc Layout｜文档三栏
- **定义**：技术网站的标配：左边目录、中间正文、右边本页大纲，一屏看到三层结构，翻文档特别舒服。
- **要点**：
  - 画面注释：目录（快速上手/基础概念/进阶用法/常见问题）| 正文 | 大纲
  - 说“三栏文档布局”，AI 会给出教科书式的阅读骨架
- **给 AI 的句式**：“三栏文档布局（Doc Layout）：左目录、中正文、右本页大纲”。

### Responsive｜响应式设计
- **定义**：不是一种布局，而是页面会跟着屏幕变形：同一个页面，电脑上三列排开，手机上收成一列，操作照样完成。
- **要点**：
  - 画面注释：电脑 / 平板 / 手机
  - 说“做响应式”，页面在手机、平板、电脑上都看得舒服
- **给 AI 的句式**：“做响应式：手机、平板、电脑上都要好看好用”。

### Single Page｜单页滚动
- **定义**：把内容全塞进一个长页面，往下滚就是全部（画面注释“往下滚，就是全部”），产品介绍、活动页最常用。
- **要点**：
  - 顺着滚一遍像听一个完整故事（一镜到底）
  - 说“单页滚动”，AI 会按阅读顺序帮你排好
- **给 AI 的句式**：“单页滚动：一个长页面按阅读顺序一镜到底”。

### Sidebar｜左侧栏
- **定义**：左边一列功能菜单、右边一大块内容区，后台管理系统的标配：找设置、报表全靠左边这列导航。
- **要点**：
  - 演示菜单：仪表盘 / 数据报表 / 用户管理 / 系统设置
  - 说“左侧栏布局”，AI 就知道你要的是工作台
  - 画面提示词：说“左侧栏布局”
- **给 AI 的句式**：“左侧栏布局（后台）：左边功能菜单，右边内容工作台”。

### Centered Column｜居中窄栏
- **定义**：内容不铺满全屏，在中间窄窄一条、两边留白，像读博客一样舒服；限宽 600-720px。
- **要点**：
  - 画面注释：限宽 600-720px / 留白
  - 演示：生活随笔博客
  - 说“居中窄栏”，AI 会把内容框在中间一栏、限个宽度，文字读起来特别顺
- **给 AI 的句式**：“居中窄栏：正文限宽 600~720px、两侧留白，像博客”。

> *收尾串联：九个布局词像点菜一样指挥 AI：卡片网格、瀑布流、分屏、顶部导航、文档三栏、响应式、单页滚动、左侧栏、居中窄栏——先想清楚要哪种架子，剩下的交给它，页面就照做了。*

## 第13 集｜Vibe Coding 术语课：CSS 布局与文字篇
> 主题：CSS 布局与文字 14 个技术术语：居中/盒模型/内边距/外边距/Flex/Grid/间距/定位/层级/溢出/吸顶/排版/衬线与无衬线/文本截断——解决“水平垂直居中要写多少行”这类让新手崩溃的 CSS 问题

### Centering｜居中
- **定义**：把元素放到容器的正中间（水平垂直居中），最省事是 Flex，Grid 用 place-items 一行搞定。
- **要点**：
  - 父元素写 display:flex + justify-content:center + align-items:center，子元素直接居中
  - Grid 更简单：place-items:center 一行搞定（画面注释 /*一行搞定*/）
  - 绝对定位（Absolute）也行，但要配合 transform 往回拉一半
  - 片头提问：水平垂直居中到底要写多少行代码？
- **给 AI 的句式**：需求里写“这个元素要在容器里水平垂直居中（Flex 写法）”，AI 直接给出三行样式。
- **代码**：
```
display: flex; justify-content: center; align-items: center;
display: grid; place-items: center; /* 一行搞定 */
```

### Box Model｜盒模型
- **定义**：CSS 的地基：每个元素都是一个盒子，从里到外四层——内容(content)、内边距(padding)、边框(border)、外边距(margin)。
- **要点**：
  - 画面注释：Content 内容 / Border 边框
  - 最容易踩的坑：设了 width:320，加 padding 和 border 后实际占宽会变大
  - 实际宽度 = content + padding×2 + border×2（画面算式：320 + 24×2 + 4×2 = 376px）
  - 画面结论：设了 width 不代表实际占这么宽
- **给 AI 的句式**：对 AI 说“用标准盒模型，注意 width 指内容区宽度、别被 padding/border 撑破布局”即可避开此坑。
- **避坑**：设了 width 不代表实际就占这么宽：加了 padding 和 border 后实际宽度会变大，算清楚这四层布局才不会乱。

### Padding｜内边距
- **定义**：内容与边框之间的距离（往里撑），越大内容越往里缩、呼吸感越强，按钮卡片好不好看八成靠它调。
- **要点**：
  - 画面注释：内容与边框之间的距离；越大呼吸感越强
  - 16~24px 是舒服区间，给太少显得挤、给太多又空
  - 演示：padding 从 0 调到 48px 的盒子动画
- **给 AI 的句式**：“按钮/卡片的内边距（Padding）给到 16~24px，别太挤”。

### Margin｜外边距
- **定义**：管元素和外面其他东西的距离（往外推）：padding 是往里撑，margin 是往外推。
- **要点**：
  - 画面注释：padding = 往里撑；margin = 往外推；管元素和外面的距离
  - 经典坑：Margin 重叠——上下两个 margin 不取和，只取较大的那个值
- **给 AI 的句式**：需求里说“这个元素与上一个之间拉开外边距（Margin）”。
- **避坑**：Margin 重叠陷阱：上下相邻元素的 margin 不会相加（mb:30px + mt:20px 实际只有 30px，取较大值）——遇到间距不对时先想想是不是重叠了。

### Flex｜弹性布局
- **定义**：一维布局利器：要么横着排要么竖着排，一次只管一个方向；父元素写 display:flex，子元素自动排成一行。
- **要点**：
  - justify-content 管主轴对齐：flex-start / center / space-between（space-between 让元素自动两端对齐）
  - align-items 管交叉轴对齐
  - 想竖着排：flex-direction 改成 column
  - demo 值：flex-start / center / space-between
- **给 AI 的句式**：“这一排按钮用 Flex 弹性布局：两端对齐（space-between）、垂直居中”。
- **代码**：
```
display: flex;
justify-content: space-between;
align-items: center;
```

### Grid｜网格布局
- **定义**：二维布局：行和列同时控制，把容器切成格子，元素往格子里放就行；repeat(3,1fr) 就是平均分三列。
- **要点**：
  - 画面注释：二维布局：行和列同时控制
  - 1fr = 弹性单位，自动按比例分配
  - 配 auto-fit + minmax：屏幕窄了自动变少列（画面演示：窄屏自动变 2 列），响应式一句话搞定
  - gap: 14px 控制格子间距
- **给 AI 的句式**：“用 Grid 网格布局做卡片区：三列、等分（repeat(3, 1fr)）、自动响应式换列”。
- **代码**：
```
display: grid;
grid-template-columns: repeat(3, 1fr);
gap: 14px;
/* 响应式：auto-fit + minmax */
```

### Space｜间距
- **定义**：说白了就是元素之间留多少空：Flex 和 Grid 里直接写 gap，比一个个加 margin 干净多了。
- **要点**：
  - 间距不是随便给的：按倍数走 4/8/12/16/24/32，整页节奏感就统一了
  - 太挤看着累，太散找不到重点（画面演示：刚好 / 太挤 / 太散）
  - 16px 是万能起步值
  - 画面注释：gap 比 margin 干净
- **给 AI 的句式**：“元素之间用 gap:16px 统一间距，间距按 4 的倍数走”。
- **代码**：`gap: 16px;`

### Position｜定位
- **定义**：控制元素放在哪、跟不跟着滚动：relative 相对自己原位挪、absolute 脱离文档流找最近的已定位祖先、fixed 直接钉在浏览器窗口。
- **要点**：
  - static：默认，在文档流里，无法用 top/left 定位
  - relative：相对自身原位置偏移（画面注释：不影响其他元素）
  - absolute：脱离文档流，相对最近已定位祖先；父元素记得加 position:relative
  - fixed：固定在浏览器窗口，页面怎么滚它都不动（如回到顶部按钮）
- **给 AI 的句式**：“这个角标用 absolute 定位到容器右上角（父容器记得 relative）”；“回到顶部按钮用 fixed 钉在窗口右下角”。
- **代码**：
```
position: relative; top: -10px; right: -10px; /* 相对自身偏移 */
position: absolute; top: 0; right: 0; /* 父级需 relative */
position: fixed; top: 20px; right: 20px; /* 固定在浏览器窗口 */
```
- **避坑**：用 absolute 时父元素要加 position:relative，否则它会跑到更外层（最近已定位祖先）去。

### Z-Index｜层级
- **定义**：决定谁压在谁上面：数值越大越靠上，弹窗被内容挡住了？拉高 z-index 就行。
- **要点**：
  - 画面注释：谁压在谁上面 / 数值越大越靠上
  - 演示：z-index: 3 的悬浮层
  - 前提：元素必须设置了 position（relative/absolute/fixed 都行）才生效
- **给 AI 的句式**：“弹窗被其他内容挡住，给弹窗加高 z-index（如 99）”。
- **代码**：`z-index: 99;`
- **避坑**：z-index 的前提是必须设置了 position：static + z-index:99 无效，relative/absolute/fixed + z-index 才生效——这是新手最常踩的坑之一。

### Overflow｜内容溢出
- **定义**：盒子装不下内容了怎么办：visible 直接溢出来难看、hidden 超出裁掉、scroll 加滚动条、auto 最智能——溢出才出现滚动条。
- **要点**：
  - visible：直接溢出，难看
  - hidden：超出部分裁掉干净（但看不到了）
  - scroll：加滚动条能滑着看
  - 卡片里文字不确定多长时，用 overflow:hidden 配合 text-overflow 准没错
- **给 AI 的句式**：“文字多了别撑破卡片：容器加 overflow:hidden（或 auto，溢出才出滚动条）”。

### Sticky｜吸顶
- **定义**：滚动到一定位置就粘在顶部不动：导航栏、通讯录字母索引、表格表头都靠它，比 fixed 聪明——只在父容器范围内吸顶，滚出父容器就跟着走。
- **要点**：
  - 最常见场景：页面导航栏，往下滚时一直钉在最上面
  - 画面演示：Nav 导航栏 + 分组标题（分组A/B/C）都粘在顶部
  - 画面注释：比 fixed 聪明——只在父容器范围内吸顶 / 滚出父容器就跟着走
- **给 AI 的句式**：“导航栏做吸顶（Sticky）：滚动时始终钉在顶部”。
- **代码**：
```
position: sticky;
top: 0;
/* 只在父容器内吸顶；滚出父容器就跟着走 */
```
- **避坑**：别拿 fixed 硬做吸顶：sticky 只在父容器范围内吸顶，fixed 会一直钉在窗口上不跟容器走。

### Typography｜排版
- **定义**：不是选个字体那么简单，核心是建立文字层级：标题最大最粗、正文中等字号、辅助信息最小最灰，用户扫一眼就知道先看什么。
- **要点**：
  - H1 标题：最大最粗，告诉人这页讲什么
  - Body 正文：中等字号、行高 1.6 左右读着不累
  - Caption 辅助：最小最灰（如时间、来源）
  - 所有文字一样大，那叫没排版；三级分明，一眼看出重点
- **给 AI 的句式**：“标题/正文/辅助文字做好层级：标题 38px/800，正文 18px、行高 1.6，辅助 14px 灰色”。
- **代码**：
```
H1 标题 38px / 800
Body 正文 18px / 1.6
Caption 辅助 14px / 灰
```

### Serif & Sans｜衬线与非衬线
- **定义**：看笔画末端有没有装饰角：Serif 衬线体（宋体/Times New Roman）笔画末端有装饰角，正式优雅有印刷感；Sans-Serif 无衬线体（黑体/Helvetica）笔画干净，屏幕更清晰。
- **要点**：
  - Serif 衬线体：正式、优雅、印刷感，适合印刷品和标题
  - Sans-Serif 无衬线体：现代、清晰、屏幕友好
  - 网页/APP/界面基本都用无衬线体
  - 选字体先想清楚：要印刷感还是要屏幕清晰
- **给 AI 的句式**：“页面字体用无衬线体（Sans-Serif，如系统黑体）；标题想有印刷感可以试衬线体”。

### Text Truncate｜文本截断
- **定义**：标题太长卡片装不下时，三行代码把超出部分裁掉、强制不换行、末尾加省略号，用户看到的是一句干净的话加三个点。
- **要点**：
  - overflow:hidden 裁掉超出部分 + white-space:nowrap 强制不换行 + text-overflow:ellipsis 加省略号
  - 想截两行：多行截断用 -webkit-line-clamp: 2
  - 列表页、卡片标题必备技能（画面注释）
  - 演示：超长标题在卡片里变成“…”，正文超两行自动截断加省略号
- **给 AI 的句式**：“卡片标题超长时做单行文本截断，超出显示省略号（多行则 clamp 两行）”。
- **代码**：
```
overflow: hidden;
white-space: nowrap;
text-overflow: ellipsis;
/* 多行截断：-webkit-line-clamp: 2 */
```

> *收尾串联：14 个术语搞定：盒模型是地基，Flex 和 Grid 是布局左右手；间距与居中负责排得舒服，定位和层级（Position/Z-Index/Sticky/Overflow）管谁在哪，排版和截断（Typography/衬线体/Text Truncate）管文字好不好看——收藏起来，写 CSS 的时候翻。*

## 第14 集｜前端 UI 外观篇：11 个词让 AI 听懂你要什么
> 主题：给 AI 描述「界面好不好看」的 11 个视觉词：视觉层级/对比度/圆角/圆角气质/阴影/分割线/透明度/渐变/毛玻璃/深色模式，外加设计令牌统管取值。

### Visual Hierarchy｜视觉层级
- **定义**：页面元素按重要程度排出的“先看哪、再看哪”顺序——用大小、颜色设计出来的视线引导。
- **要点**：
  - 眼睛先看哪，是设计出来的
  - 标题最大最显眼，说明文字小一点、灰一点
  - 按钮用颜色跳出来
  - 什么都一样大 = X 没有层级，用户不知道该看哪
- **给 AI 的句式**：写：“标题、正文、按钮把视觉层级拉开：主标题最大，说明文字小且灰，重点按钮用颜色跳出来”。
- **避坑**：别把所有文字做成一样大一样黑——没有层级，用户不知道该看哪(画面：X没有层级)。

### Contrast｜对比度
- **定义**：文字与背景之间的明暗差距——差得够远，才读得舒服。
- **要点**：
  - 对比度=两者差距
  - 浅灰字配浅灰底，眼睛得使劲找
  - 正文和背景的对比一定要够
  - 别为了“高级感”把字弄成半透明
- **给 AI 的句式**：写：“正文与背景对比度拉够，灰字配灰底的模糊配色不要，保证清晰易读”。
- **避坑**：别为高级感把正文做成浅灰配浅灰或半透明——看不清(字幕原文)。

### Border Radius｜圆角
- **定义**：把方形尖角磨圆的弧度值——直角严肃、圆角亲和。
- **要点**：
  - 直角→圆角，气质从严肃变友好；圆一点就亲和一点
  - 演示刻度：0px / 16px / 40px / 80px
  - 磨太少没感觉，磨太多变成胶囊型
  - 一般按钮用 8~16px 挺舒服
- **给 AI 的句式**：给 AI 具体数值：“按钮圆角用 8px、卡片 16px，气质做得友好一点”。
- **避坑**：圆角别乱磨——太少没感觉，太多(如 80px)会变成胶囊型。

### Corner Feel｜圆角的气质
- **定义**：全站圆角统一后形成的整体性格——小元素小圆角、大卡片大圆角，比例一致。
- **要点**：
  - 最忌“各圆各的”(X各圆各的)——像拼凑的
  - 定一个全站通用值(✓全站统一 r=12)
  - 小元素小圆角、大卡片大圆角，比例要一致
  - 圆角统一了，界面才有自己的性格
- **给 AI 的句式**：写：“全站圆角统一一套数值体系：按钮 8px、卡片 16px，按元素大小成比例，别各圆各的”。
- **避坑**：按钮 4px、卡片 20px 混着放像拼凑的——圆角要全站统一(字幕原文)。

### Shadow｜阴影
- **定义**：给元素加投影让它看起来浮在页面上——阴影越重，离你越近(层级越高)。
- **要点**：
  - 三级示意：贴在纸上→微微浮起→弹出来了
  - 阴影越重，离你越近
  - 弹窗(如确认删除)=最重阴影，告诉用户它现在在最上面
  - 所有东西都加一样的阴影=等于没加
- **给 AI 的句式**：写：“卡片加一层淡阴影微微浮起，弹窗用最重的阴影压在最上层，拉开层级”。
- **避坑**：别给所有元素加一样深的阴影——层级感消失，等于没加。

### Divider｜分割线
- **定义**：一条细分隔横线——内容太多分不开时，画条线让分组清楚。
- **要点**：
  - 没有分割线=一坨
  - 设置页里“通知设置”和“隐私设置”两组之间画一条
  - 内容太多分不开？画条线就清楚了
  - 间距够大时留白本身就是分割，线别到处画
- **给 AI 的句式**：写：“设置页把通知和隐私两个分组之间加一条 Divider 分割线隔开”。
- **避坑**：别到处划线——间距足够时用留白分组，线多了反而乱。

### Opacity｜透明度
- **定义**：元素不透明程度——不重要的东西淡一点，注意力自然落在重要信息上。
- **要点**：
  - 100% 实色 / 50% 半透 / 15% 几乎看不见
  - 主内容实色，辅助淡一点，装饰再淡一点
  - 示例：产品名称实色、描述次之、次要信息(2024)最淡
- **给 AI 的句式**：写：“次要信息把 Opacity 降到 50%~60%，主内容保持 100% 实色”。

### Gradient｜渐变
- **定义**：一个颜色慢慢过渡成另一个颜色——纯色太闷，给它加个方向。
- **要点**：
  - 线性·横向 / 线性·纵向 / 径向(从中心往外扩散)
  - 纯色太闷？给它加个方向
  - 按钮、头图用渐变=视觉焦点(渐变按钮示例)
  - 正文区域别用渐变，影响阅读
- **给 AI 的句式**：写：“主按钮做横向线性渐变(主色→辅色)，让它成为视觉焦点”。
- **避坑**：正文区域别用渐变——影响阅读(字幕原文)。

### Backdrop Blur｜毛玻璃
- **定义**：半透明元素把背后内容模糊掉——后面的东西隐约可见但看不清，比纯白底有层次。
- **要点**：
  - 半透明加模糊，后面的东西隐约可见
  - 吸顶导航栏常见：滚动时内容透出来但不干扰阅读
  - 普通白底完全挡住后面内容 = X 没有层次感
  - 弹窗和悬浮面板也常用
- **给 AI 的句式**：写：“顶部导航栏做毛玻璃效果：半透明并把背后滚动内容模糊(backdrop blur)，隐约可见”。
- **代码**：`backdrop-filter: blur(18px)`
- **避坑**：别用纯白底把后面内容完全挡住——没有层次感(画面：X没有层次感)。

### Dark Mode｜深色模式
- **定义**：黑底浅字的暗色主题——不是把白变黑那么简单，文字、阴影、边框都要配套调。
- **要点**：
  - 深色模式不是把白变黑那么简单
  - 文字用浅灰(不刺眼)，别用纯白
  - 阴影在深色背景上看不见→换成微弱发光
  - 边框调浅
- **给 AI 的句式**：写：“做深色模式：背景深色，正文浅灰不用纯白，卡片阴影改成微弱发光、边框调浅”。
- **避坑**：差的深色模式=纯黑底加白字，眼睛疼(字幕原文)——阴影在深色下看不见，要换发光。

### Design Token｜设计令牌
- **定义**：把颜色/圆角/字号/间距等值存成带名字的 CSS 变量(tokens.css)——引用同一个值，改一处全站跟着变。
- **要点**：
  - 令牌库 tokens.css：--color-primary / --color-secondary / --space-md / --radius-md / --font-lg
  - 引用同一个值：主按钮、卡片标题、标签都引用主色
  - 改一个地方，全站跟着变(--color-primary 从 #7C3AED 改为 #0891B2，全部同步变色)
  - 大团队都这么干，不然改个颜色得翻几百个文件
- **给 AI 的句式**：写：“颜色、圆角、间距定义成 Design Token(CSS 变量)，组件全部引用变量，以后换主题只改 tokens 一处”。
- **代码**：`--color-primary:#7C3AED; --color-secondary:#DB2777; --space-md:16px; --radius-md:12px; --font-lg:20px`
- **避坑**：别把颜色值散落写死在几百个文件里——换个颜色要翻遍全站(字幕原文)。

> *收尾串联：收尾串联：11 个词按“先看哪→读得清→有气质→统管”串起来——视觉层级管视线顺序，对比度管可读性；圆角、圆角气质、阴影、分割线、透明度、渐变、毛玻璃、深色模式塑造外观风格；最后设计令牌把颜色/圆角/间距变量化，改一处全站同步。下期讲布局和排版。*

## 第15 集｜前端交互黑话大全：12 个动画 + 鼠标术语一次讲清
> 主题：页面交互黑话 12 个：动画类 5 个(Transition/Animation/Easing/Spring/Fade In-Out)讲画面怎么动，鼠标交互类 7 个(Hover/Active/Focus/Drag/Disabled/Cursor/Selection)讲用户怎么点。

### Transition｜过渡
- **定义**：一个状态变成另一个状态的过程(需要触发)——加了过渡，浏览器帮你把中间帧补上，平滑变过去。
- **要点**：
  - 需要一个触发条件(如鼠标悬停)
  - 无过渡=瞬间完成，啪一下就跳过去
  - 颜色、大小、位置都能平滑过渡
  - 示例：有过渡 transition: 0.3s
- **给 AI 的句式**：写：“hover 变色/位移加 transition 0.3s 平滑过渡，不要瞬间跳变”。
- **代码**：`transition: 0.3s`
- **避坑**：Transition 要触发条件；Animation 能自己循环跑——两者别混用。

### Animation｜动画
- **定义**：用关键帧定义起点/中间/终点、可自动循环的动画——不需要任何人触发，自己跑。
- **要点**：
  - 不需要触发，自己就能跑起来
  - @keyframes float 定 0%→50%→100% 关键帧
  - 示例：图标上下浮动 2s 循环无限次
  - 适合浮动、加载这类装饰性自运动
- **给 AI 的句式**：写：“给这个图标加上下浮动的 Animation：2s 一个循环、infinite，不用鼠标触发”。
- **代码**：`@keyframes float { 0% { transform: translateY(0) } 50% { transform: translateY(-30px) } 100% { transform: translateY(0) } }  .icon { animation: float 2s infinite }`

### Easing｜缓动
- **定义**：动画的速度曲线(缓动函数)——同样从 A 到 B，决定是匀速、先慢后快还是两头慢。
- **要点**：
  - linear 匀速
  - ease-in 先慢后快
  - ease-in-out 两头慢、中间快
  - 用对了才像真实世界运动：有惯性、有停顿，不像机器死板
- **给 AI 的句式**：写：“过渡/动画用 ease-in-out 两头慢的缓动曲线，别用生硬的匀速”。
- **避坑**：缓动不用或乱用，动画就会机械死板像机器。

### Spring｜弹性
- **定义**：带弹簧物理感的动画——普通动画到目标就停，弹性动画会冲过头(overshoot)再回弹收敛。
- **要点**：
  - 位移曲线 + overshoot 冲过头 → 回弹收敛
  - 手感参数示例：damping 8、stiffness 100
  - 弹窗落下先多走一截，再晃两下稳住
  - 弹窗出现、按钮点击用它会特别有手感
- **给 AI 的句式**：写：“弹窗/提示出现用 Spring 弹性动画，带一点 overshoot 冲过头再回弹的感觉”。
- **代码**：`damping: 8, stiffness: 100`

### Fade In / Out｜渐入渐出
- **定义**：淡入(fade in)/淡出(fade out)——切换内容时旧的慢慢消失、新的慢慢出现，比硬切柔和。
- **要点**：
  - fade in 慢慢出现 / fade out 慢慢消失
  - 切换内容比直接硬切柔和得多
  - 通常配位移动画：旧的往上走，新的从下面上来，过渡有层次
- **给 AI 的句式**：写：“内容切换用 Fade In/Out：旧的淡出上移、新的从下方淡入，别硬切”。
- **代码**：`opacity: 0→1; translateY: 20→0`

### Hover｜悬停
- **定义**：鼠标指针放上去时的状态反馈——变个色、浮起来一点、阴影深一点，让用户知道这东西能点。
- **要点**：
  - 对照组：有悬停反馈 vs 无悬停反馈
  - 反馈方式：变个色、浮起来一点、阴影深一点
  - 没有悬停反馈的按钮像假按钮，用户不确定能不能按
- **给 AI 的句式**：写：“所有可点元素加 hover 反馈：变色 + 上浮一点 + 阴影加深”。
- **避坑**：没有 hover 反馈的按钮=假按钮，用户根本不确定能不能点(字幕原文)。

### Active｜按下
- **定义**：鼠标点下去那一瞬间的状态——按钮得有被“按瘪”的实感。
- **要点**：
  - 按下瞬间要有被按瘪的感觉
  - 做法：往下挪一像素、阴影收一收
  - 只有 hover 没有按下=像按空气按钮：手指下去了界面纹丝不动
- **给 AI 的句式**：写：“按钮加 active 按下反馈：整体下移 1px、阴影减弱，有按下去的实感”。
- **避坑**：只做 hover 不做 active，按下毫无反应，像按空气按钮(字幕原文)。

### Focus｜聚焦
- **定义**：键盘焦点所在处的可见状态——用 Tab 键在表单里跳时，一个明显的焦点描边告诉用户当前停在哪。
- **要点**：
  - Tab 键依次聚焦输入框，要有焦点描边
  - 对照组：有焦点描边 vs 移除了 outline
  - 为好看移除 outline 又不补替代方案=键盘用户根本找不到自己在哪，只能瞎按
- **给 AI 的句式**：写：“输入框保留清晰的 focus 描边，键盘 Tab 到哪个控件要看得见”。
- **避坑**：别为美观移除 outline 却不给替代焦点样式——键盘用户(无障碍)直接迷路。

### Drag｜拖拽
- **定义**：按住一个元素拖着走——松手放到新位置或回到原位。
- **要点**：
  - 按住→拖动→松手(放到新位置或回到原位)
  - 卡片排序、滑块调节这类交互都离不开拖拽
  - 拖动时给点旋转角度和阴影，像真的捏着一张卡片，手感更真实
- **给 AI 的句式**：写：“卡片做成可拖拽排序：拖起时带轻微旋转和阴影，松手落到新位置”。

### Disabled｜禁用
- **定义**：控件的不可用状态——置灰、点不动，鼠标指针也变成禁止符号，从视觉到交互都告诉用户“现在用不了”。
- **要点**：
  - 表单未填写完成→提交按钮暂不可用(灰、点不动)
  - 不只是颜色变灰，鼠标指针也得变成禁止符号
  - 从视觉到交互都告诉用户：这个现在用不了
- **给 AI 的句式**：写：“表单没填完时提交按钮用 disabled 置灰，鼠标放上去显示禁止光标”。
- **避坑**：只变灰不换光标，用户还以为页面卡了(字幕原文)。

### Cursor｜鼠标指针
- **定义**：鼠标光标形状(cursor)——指针暗示接下来能做什么操作。
- **要点**：
  - 普通文字=默认箭头指针(cursor: default)
  - 按钮=小手(cursor: pointer)
  - 输入框=文本光标
  - 按钮上显示文本光标，谁知道能不能点
- **给 AI 的句式**：写：“按钮加 cursor: pointer，鼠标移上去是小手而不是箭头”。
- **代码**：`cursor: default / cursor: pointer`
- **避坑**：指针搞反很让人困惑——可点按钮上却是文本光标(字幕原文)。

### Selection｜选中高亮
- **定义**：鼠标拖动滑选文字时的高亮底色(::selection)——默认蓝可以换成品牌色。
- **要点**：
  - 鼠标拖动选中的那块底色就是选中高亮
  - 默认选中色 vs 品牌选中色(示例薄荷绿)
  - 细节虽小，但整个页面的精致感会提升不少
  - 用户会觉得“这个网站挺用心的”
- **给 AI 的句式**：写：“把文字选中高亮改成品牌色(::selection)，别用浏览器默认蓝”。
- **代码**：`::selection { color: #1A1B26; background: #9ECE6A }`

> *收尾串联：收尾串联：12 个词分两类——过渡/动画/缓动/弹性/渐入渐出这 5 个管“画面怎么动”；悬停/按下/聚焦/拖拽/禁用/鼠标指针/选中高亮这 7 个管“用户怎么跟页面互动”。搞懂这 12 个词，前端交互黑话就听得懂一半。*

## 第16 集｜网络与地址：从域名到重定向，9 个词搞懂互联网
> 主题：网络与地址 9 词一条链路：域名(Domain)→DNS 解析→URL 结构→HTTP/HTTPS 传输→Cookie 会话记忆→CDN 加速→端口分服务→重定向搬家。

### Domain｜域名
- **定义**：网站的好记名字——代替难记的 IP 地址。
- **要点**：
  - 域名=网站的好记名字，代替难记的 IP 地址(如 110.242.68.66)
  - 每台服务器都有一串数字地址叫 IP
  - www.baidu.com 用点分段：www=子域、baidu=主体、com=后缀
- **给 AI 的句式**：页面/接口地址别写死 IP，需求里直接说域名(子域，如 api.example.com)。

### DNS｜域名系统
- **定义**：互联网的电话簿——把域名翻译成服务器 IP。
- **要点**：
  - 域名是给人记的，机器要的是 IP
  - 查法示例：baidu.com → 110.242.68.66
  - 流程：你问 DNS → DNS 查完把 IP 给你 → 你拿 IP 去找真正的服务器

### URL｜统一资源定位符
- **定义**：地址栏里那一长串——一份完整的「去哪里、拿什么」说明书。
- **要点**：
  - 结构：https + www.baidu.com + :443 + /search + ?q=hello + #top
  - 依次是：协议→域名→端口→路径→参数→锚点
- **给 AI 的句式**：给 AI 写跳转/资源地址时给完整 URL；开发用 localhost:端口，线上用 https 域名。
- **代码**：`https://www.baidu.com:443/search?q=hello#top`

### HTTP｜超文本传输协议
- **定义**：浏览器和服务器之间的对话规则——Request 请求、Response 响应，一来一回。
- **要点**：
  - 浏览器发请求(要哪个页面)→服务器回响应(把内容给你)
  - 一来一回就完成一次交互
  - 打开一个网页=背后几十上百次请求响应

### HTTPS｜安全 HTTP
- **定义**：HTTP 加个 S(Security)——传输前把数据加密，明文变乱码，截获也看不懂。
- **要点**：
  - HTTP + S(Security 安全)
  - HTTP 明文：发送 password=123456，中间路由器能偷看
  - HTTPS 加密：发送 %$#@!*&^ 乱码，截获也看不懂
  - 地址栏左边的小锁 = HTTPS 的标志
- **给 AI 的句式**：凡涉及账号密码的页面/接口必须走 HTTPS，禁止明文 HTTP 传密码。

### Cookie｜小纸条
- **定义**：服务器塞给浏览器的小纸条(身份信息)——HTTP 不记事，靠它认出你。
- **要点**：
  - HTTP 不记事：两次请求，服务器根本不知道是同一个人
  - Cookie=服务器给你的小纸条(示例 session_id=abc123)
  - 浏览器存下来，下次请求把纸条带上，服务器一看：是你啊(已登录)
  - 购物车、登录状态，靠的都是它

### CDN｜内容分发网络
- **定义**：把网站的静态内容(图片/视频)提前复制到全国各地节点——就近取，不用跑源站。
- **要点**：
  - 源站在杭州、你在黑龙江：每次请求跑半个中国(远、慢)
  - CDN=把内容搬到你家门口(各地 CDN 节点，近、快)
  - 刷视频、看图片秒开，背后都是 CDN

### Port｜端口
- **定义**：一台服务器(一个 IP)上区分不同服务的“房间号”——IP 是大楼地址，端口是房间号。
- **要点**：
  - 一台服务器可同时跑网页、数据库、远程连接，共用 IP
  - 端口=服务器大楼里的房间号
  - 默认：HTTP :80、HTTPS :443、SSH :22、MySQL :3306
  - :8080 备用、:3000 开发常用
- **给 AI 的句式**：开发时让 AI 起本地服务写清端口(如 3000)；线上默认 443/80，别写错端口。
- **代码**：`HTTP:80 · HTTPS:443 · SSH:22 · MySQL:3306 · 备用:8080 · 开发:3000`

### Redirect｜重定向
- **定义**：服务器告诉你“搬这儿了”——浏览器收到指令自动跳到新地址。
- **要点**：
  - 访问 old-page.com，服务器说这个页面搬家了，给新地址
  - 浏览器自动跳到 new-page.com
  - 301 永久搬走 / 302 临时搬走
  - 场景：网站改版、域名更换、HTTP 跳 HTTPS
- **给 AI 的句式**：旧域名/旧链接要跳新站时对 AI 说清配 301(永久)而不是 302。
- **代码**：`301 永久搬走 / 302 临时搬走`

> *收尾串联：收尾串联：九个词串起来——域名是名字，DNS 查地址，URL 是完整路径，HTTP 管对话，HTTPS 加了密，Cookie 记住你，CDN 让你快，端口分服务，重定向帮你搬家。搞懂这些，后端网络这块就算入门了。*

## 第17 集｜看完这 13 个术语，后端不再玄学
> 主题：后端 13 术语=一趟数据的一生：数据在路上 7 个(API/JSON/CORS/数据校验/入队/幂等/消费者)+到站后 6 个(浏览器存储/数据库/写入数据库/SQL/事务/数据库迁移)。

### API｜接口(API)
- **定义**：后端能力对外开放的“柜台窗口”——一句话定死：我能给你什么、你得按什么格式来问。
- **要点**：
  - Application Programming Interface
  - 你在窗口外只能递一张纸条，写上我要什么，等它递东西出来
  - 柜台后面的机器怎么分工，你一概不知道也不用知道
  - 你的 App 只跟它打交道

### JSON｜JSON(JavaScript Object Notation)
- **定义**：接口传数据的标准格式——键值对、一坨花括号，人看得懂、机器也读得动。
- **要点**：
  - 纸条的格式：键和值一对一对写(名字:张三、手机号:138****、items:[1,2])
  - 流行就一个原因：人看得懂，机器也读得动
  - 前后端谁都不用迁就谁
  - 说“接口返回数据”，十有八九就是这么一坨 JSON
- **代码**：`{"name": "张三", "phone": "138****", "items": [1, 2]}`

### CORS｜跨域资源共享(CORS)
- **定义**：浏览器的跨域门禁——A 站页面代码想请求 B 站接口，默认拦下；除非 B 站在响应头挂牌子放行。
- **要点**：
  - Cross-Origin Resource Sharing
  - your-site.com 的页面代码想去请求 api.other.com，浏览器默认拦下
  - 除非对面在门口挂个牌子：响应头 Access-Control-Allow-Origin 写明“允许 A 来”
  - 前端改不了，得让后端/网关在响应头放行
- **给 AI 的句式**：前端报跨域时写：“后端把接口响应头加上 Access-Control-Allow-Origin，放行前端这个域名”。
- **代码**：`Access-Control-Allow-Origin`
- **避坑**：控制台报错里带 CORS 三个字母，八成是对面没给你开门——跟你代码写得对不对没关系，去查对面的响应头(画面原文)。

### Validation｜数据校验
- **定义**：数据安检——手机号填 abc、年龄填负数，别进来，直接打回并附 400。
- **要点**：
  - 安检：-abc / -138... 这类非法输入直接打回去
  - 回 400 Bad Request
  - 页面上那点提示，打开开发者工具就能绕过
- **代码**：`400 Bad Request`
- **避坑**：别只信前端校验——前端红字提示能绕过，后端这一关必须自己再查一遍，谁都不能信(字幕原文)。

### Enqueue｜入队
- **定义**：把当场办不完的活儿(发短信/压视频/算报表)扔进队列排队，先回请求“已收到”。
- **要点**：
  - 有些活儿当场办不完→先扔进队列里排着
  - 先回请求“已收到，号是 7”，用户不用一直转圈
  - 队列按序处理：已收到 → 已处理

### Idempotency｜幂等
- **定义**：同一件事办 100 次，结果跟办一次一样——网络抖、手抖多点几下，只生效一次。
- **要点**：
  - 网络会抖、页面卡住时人会多点两下三下
  - 支付账上只能扣一次(示例：#A7 ¥200 只入账一行，重复的“这个编号见过了”)
  - 做法：每次请求带一个唯一编号，服务端见过的编号一律不再处理
  - 唯一编号=请求的身份证号
- **避坑**：支付/下单这类接口不做幂等，用户重复点击就会重复扣款。

### Consumer｜消费者
- **定义**：队列另一头干活的那位——不生产任务，只从队头拿一个、办一个、再拿下一个。
- **要点**：
  - Consumer 1/2/3 并行处理队列里的消息
  - 中途挂掉的任务不能被吞掉，要重新塞回队列让别人接手
  - 队列+消费者这套东西图的是人多好干活，挂一个也不塌
- **避坑**：消费者处理中挂掉，任务要回队列重来，不能吞(画面原文)。

### Browser Storage｜浏览器存储
- **定义**：你电脑上的本地“小抽屉”——localStorage 关掉浏览器还在，sessionStorage 关掉标签页就清空。
- **要点**：
  - localStorage：关掉浏览器还在
  - sessionStorage：关掉标签页就清空
  - 写在用户自己的机器上，用户清一次缓存就没了
  - 只配放“上次选的城市、主题偏好”这类丢了也不心疼的数据
- **给 AI 的句式**：主题偏好、上次选的城市这类丢了不心疼的数据，让 AI 存 localStorage。
- **代码**：`localStorage / sessionStorage`
- **避坑**：余额、权限标记，一件都不许放浏览器存储——用户清一次缓存就没了(画面原文)。

### Database｜数据库
- **定义**：服务器上的档案柜——放在服务器上、断电不丢、几万个人能同时读写，和浏览器小抽屉是两回事。
- **要点**：
  - 放在服务器上，断电不丢
  - 几万个人能同时来读写
  - 像一整面墙的档案柜，一格一格分好类，谁都能查但得按规矩查

### Database Write｜写入数据库
- **定义**：往数据库写数据——塞进去比拿出来贵：读一次约 1ms，写一次约 8ms(要改数据、改索引、记日志)。
- **要点**：
  - 读一次 1ms / 写一次 8ms(改数据·改索引·记日志)
  - 写比读常常慢好几倍
  - 能在一次写入里办完的事，别拆成十次写
- **避坑**：写放大(一次写入拆成十次)是拖垮后端的常见死法之一(字幕原文)。

### SQL｜SQL(Structured Query Language)
- **定义**：跟数据库说话用的那门语言——长得像英文句子，你写“想要什么”，它自己决定怎么翻柜子。
- **要点**：
  - 示例：从 users 表挑 city=杭州、按名字排序、取前 20 条
  - 你写的是想要什么，数据库自己决定怎么找
  - 和写普通代码不一样：写代码你管步骤，写 SQL 你管结果
- **代码**：`SELECT name, city FROM users WHERE city = '杭州' ORDER BY name LIMIT 20`

### Transaction｜事务
- **定义**：把多步操作捆成一个包裹——转账 A 扣 200、B 加 200 必须一起成功，或一起不算。
- **要点**：
  - 最经典例子：转账，从 A 扣 200 给 B 加 200，两步必须一起成或一起不算
  - 没有事务：A 扣完、B 没加成(机器断)，合计少了 200
  - 有事务：中间任何一步出事，整个包裹退回去(ROLLBACK)，账上跟没发生过一样
  - 提交叫 COMMIT，退回叫 ROLLBACK
- **代码**：`COMMIT / ROLLBACK`
- **避坑**：扣款+入账这类多步写不加事务，扣完断了那 200 就凭空蒸发(字幕原文)。

### Migration｜数据库迁移
- **定义**：改表结构(如给 users 表加 city 字段)还不能把线上数据弄丢——老规矩三步走。
- **要点**：
  - 三步走：先加字段、允许为空 → 回填历史数据 → 最后加非空约束
  - 加字段示例：users 表新增 city(旧行 NULL，再回填杭州/北京/成都…)
  - 一步到位去改线上服务=当场报错给你看
  - 迁移脚本要能反复跑，也要能在出事的时候退回去
- **避坑**：别直接加非空约束——先加字段允许为空、回填历史数据，最后才上约束；脚本要可重跑、可回退。

> *收尾串联：收尾串联：13 个词=一趟数据的一生——点一下下单，背后是 13 道关：API 窗口→JSON 格式→CORS 门禁→Validation 安检→Enqueue 排队→Idempotency 防重→Consumer 接手；数据到站后：Browser Storage 小抽屉(靠不住)→Database 档案柜→Database Write 写入要省→SQL 说话→Transaction 上锁→Migration 扩容改表。*
