# 对接契约模板（复制即用）

> 用法：模板 A 定契约 → B/C 定结构与态 → D 向 AI 提词 → E 联调验收。
> 原则：**能写进表里的事，不要靠口头约定**；表里没有的，联调时一定会吵。

## 模板 A：接口契约表（一个端点一行）

| 端点 | 方法 | 路径 | 请求参数 | 请求体字段 | 成功响应 | 失败状态码 | 幂等 |
|---|---|---|---|---|---|---|---|
| 订单列表 | GET | `/api/v1/orders` | `page,pageSize,status,keyword` | 无 | `200` + 分页包装 | 400/401/403/500 | 是 |
| 建单 | POST | `/api/v1/orders` | 无 | `customerId,items[],remark` | `201` + 新单 `id` | 400/401/409/422/500 | 否（带幂等键）|
| 改备注 | PATCH | `/api/v1/orders/{id}` | 无 | `remark`（缺席=不改） | `200` | 400/401/403/404/409 | 否 |
| 删单 | DELETE | `/api/v1/orders/{id}` | 无 | 无 | `204` | 401/403/404/409 | 是 |

写完自检：**另一个人只看这张表，能不能写出调用代码？** 不能就是还没定完。

## 模板 B：统一响应包装 + 分页

```json
// 成功（列表）
{
  "code": 0,
  "message": "ok",
  "traceId": "4bf92f3577b34da6",
  "data": {
    "items": [
      { "id": "1859274610392847360", "orderNo": "SO20261026001", "status": "Paid", "amount": 128.50, "createdAt": "2026-10-26T10:30:00+08:00" }
    ],
    "page": 1, "pageSize": 20, "total": 137
  }
}

// 失败（同一个外层结构，data 为 null）
{
  "code": 30012,
  "message": "库存不足，可售 3 件",
  "traceId": "4bf92f3577b34da6",
  "data": null
}
```

要点（逐条都是坑）：
1. `id` 用**字符串**——`1859274610392847360` 超过 2⁵³−1，用数字会被 JS 改成 `1859274610392847362`。
2. `createdAt` 带时区偏移；`status` 用字符串枚举。
3. `total` 与 `items` 同一时刻取；深分页场景改用 `nextCursor` 并声明没有 total。
4. `traceId` 回给前端——用户报障时能直接定位日志。

## 模板 C：错误码分段表

| 段 | 含义 | HTTP 状态码 | 例子 | 前端该做什么 |
|---|---|---|---|---|
| `0` | 成功 | 200/201/204 | — | 正常渲染 |
| `1xxx` | 参数与格式 | 400 / 422 | `10001` 必填缺失、`10002` 手机号格式错 | 定位到字段旁提示 |
| `2xxx` | 认证与权限 | 401 / 403 | `20001` 令牌过期、`20002` 无该功能权限 | 401→跳登录；403→无权限态 |
| `3xxx` | 业务规则 | 409 / 422 | `30012` 库存不足、`30013` 状态不允许 | 弹业务提示，别重试 |
| `9xxx` | 系统内部 | 500 / 502 / 503 / 504 | `90001` 未捕获异常 | 通用错误态 + 重试按钮 |

**约定**：错误码只增不改不删；每个码必须挂在固定 HTTP 状态码下；面向用户的文案与面向程序的码分开。

## 模板 D：给 AI 的两段提词

### D-1 让 AI 产出「后端接口契约」

```
按下面的业务需求产出 REST 接口契约，先给契约表，再给真实 JSON 示例，不要直接写代码。
业务：【一句话说清这个功能谁在用、干什么】
资源：【如 订单】，需要哪些操作：【列表/详情/新建/修改/删除】
约束：
1. 路径带版本前缀 /api/v1；列表用 page/pageSize + total。
2. 外层统一 { code, message, traceId, data }；code 按分段：0 成功、1xxx 参数、2xxx 权限、3xxx 业务、9xxx 系统。
3. 字段名统一小驼峰；长整型 id 一律字符串；时间用带时区的 ISO 8601；枚举用字符串并给全部取值。
4. 逐个端点标注：可能的失败状态码（400/401/403/404/409/422/500）与对应业务码。
5. 修改类接口标明「字段缺席 = 不改，显式 null = 清空」；新建类接口标明是否需要幂等键。
```

### D-2 让 AI 产出「前端消费这组接口的代码」

```
按附上的接口契约实现前端对接，不要改字段名和结构。
要求：
1. 统一请求层：Base URL 走环境变量；自动带 Authorization 头；统一解析 { code, message, data }。
2. 状态码分流：401→清令牌并跳登录；403→渲染无权限态；409/422→按业务码显示对应字段或提示；5xx/超时→错误态 + 重试按钮（仅幂等接口可自动重试）。
3. 每个数据区必须有四态：加载（首屏骨架屏）、空（引导文案）、错误（说明 + 重试）、无权限。
4. 提交类按钮请求期间禁用；新建请求带 Idempotency-Key（UUID）。
5. 列表页：筛选/排序变化时回到第 1 页；搜索输入用防抖；分页参数与契约里的名字一致。
6. 失败文案说人话，不要把后端的 message 原样透传。
```

## 模板 E：联调验收清单（打勾才算完）

**契约层**
- [ ] 每个端点的方法、路径、请求字段、响应字段、错误码都在表里，无「口头约定」
- [ ] 用真实请求抽查一个接口，返回结构与文档一致（不是「应该一致」）
- [ ] 字段命名风格统一，长整型 ID 为字符串，时间为带时区格式
- [ ] 更新接口的「缺席 / null / 空值」三种语义验证过
- [ ] 枚举取值全集有对照表，前端未靠猜

**错误与鉴权层**
- [ ] 400、401、403、409、422、500 各造一次，前端表现各不相同且合理
- [ ] 令牌过期时链路正确：静默刷新 → 仍失败则跳登录，不出现无限重试
- [ ] 无权限时提示「无权限」，没有误跳登录页
- [ ] 错误提示里没有堆栈、表名、内部主机名

**跨域与部署层**
- [ ] 生产域名下浏览器控制台零跨域报错
- [ ] 带凭证请求未使用 `*` 通配符
- [ ] `OPTIONS` 预检能被网关正确放行
- [ ] 代码里没有写死的 IP，环境地址来自配置

**交互层**
- [ ] 四态齐全：加载 / 空 / 错误 / 无权限
- [ ] 提交按钮请求期间禁用，重复提交在服务端也被拦（幂等键生效）
- [ ] 超时、断网各演一次：有提示、有重试、已填内容没丢
- [ ] 列表筛选后空结果 ≠ 还没有数据的文案

**治理层**
- [ ] 接口文档随代码生成或与代码同源（OpenAPI），不是手写后失同步
- [ ] 本次变更标明了是否破坏性；破坏性变更已升版本
- [ ] 报错时用户能给出 traceId（或界面上可复制）

## 模板 F：.NET 侧易踩的三个默认值

| 默认行为 | 后果 | 契约里怎么写 |
|---|---|---|
| System.Text.Json 默认 camelCase | DTO 写 `OrderNo`，实际返回 `orderNo` | 明确「以小驼峰为准，后端负责转换」|
| 枚举默认序列化为数字 | 前端收到 `3` 只能猜 | 注册 `JsonStringEnumConverter`，或契约附对照表 |
| 未注册异常处理时错误结构不统一 | 500 时返回堆栈，与其他错误结构不一致 | 统一异常中间件，输出同一个 `{ code, message, traceId, data }` |
